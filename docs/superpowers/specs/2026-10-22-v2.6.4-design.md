# Football Tracker v2.6.4 design

Baseline: clean local/remote main at `e97d391fc763f5f146cc116e25fb2aad60189fd9`,
version 2.6.3. This implements the user's supplied v2.6.4 specification; the user
requests analysis, planning, implementation, verification and release in one run.

## Findings and approach

The Honors name function reads `name` before the existing `playerFullName`
helper, although registration stores a compact name separately from `fullName`.
Use the common helper first and retain the historical fallback and existing links.

The Pitch grows because `tallTeamPitch` switches its aspect ratio. Remove that
team-only size variation. Explore coordinates against rendered icon, rating,
crest, name, statistics, vacancy and hit-target boxes within a fixed 3:4 pitch,
at widths 264, 320, 375 and 390. Keep all existing visual sizes and information.
If a pathological formation cannot fit, quantify the remaining constraint rather
than resize or hide content. Official and Match Pitch defaults remain unchanged.

Selection remains the v2.6.3 dedicated selector. A subsequent presentation-only
assignment moves selected DEF (4+) and MID (4+) players to left/right outer
positions using their scoped LB/RB and LM/RM minutes. Expose the existing cached
position-minute map instead of computing timelines or caching another index.
Choose distinct edge players by maximum combined relevant minutes; ties use
selection order then player ID. With no relevant minutes preserve the order.
Do not alter quotas, scores, eligibility, selected players or historical team IDs.

Initial instrumentation confirms News derives season analytics before processing
all matches and tests every roster player for every match. Latest Changes also
builds per-match contribution events that it discards. Iterate actual participants
in original roster order (including duplicate-roster semantics), preserve the
targeted player milestone path, and add an optional contribution-event switch
whose default preserves the current API. Latest Changes alone opts out.

Measure league-prefix standings, player snapshots and monthly award derivation.
Prefer day grouping and reuse of existing canonical calculations. Retain only
demonstrated wins with exact result equivalence. For knockout News checkpoints,
skip official calls only when completion is provably impossible; use the official
engine for all decisions and conservatively fall back for legacy/malformed data.
No winner/tie/replay rule is duplicated or changed.

## Correctness and release gates

- REV13, MOM, award policy 2, official Best XI, 40% eligibility and competition
  operations remain unchanged. No storage, sync, navigation or PWA migration.
- Existing array-item revision and immutable Store invalidation remains the
  source-update contract; avoid hashing payloads or unbounded retained histories.
- Compare full outputs against archived v2.6.3 for News, Latest Changes,
  milestones, league snapshots, monthly/official awards and records after edits,
  deletions, roster changes and malformed histories.
- Record before/after medians and call counts at one and three seasons, with
  cold/warm/filter/edit/delete cases, memory implications and non-improvements.
- Run full tests, TypeScript, existing Oxlint command, production build and diff
  checks, then independent review. Report actual browser verification accurately.
- Set all release metadata to 2.6.4, commit, normal-push origin/main and verify
  Pages build/deploy plus the public runtime version. Do not release blockers.
