# Football Tracker v2.6.7 통합 업데이트

저장소: https://github.com/leedoyoub/football-tracker

현재 확인된 기준 버전은 v2.6.6이며, 이번 작업의 최종 목표 버전은 **v2.6.7**이다.

이번 업데이트는 선수 상세정보 UI 개선, Back 버튼 접근성, 경기 정보 수정 기능, 리그·컵 테이블 정렬 및 디자인 통일, 전체 앱 성능 최적화를 통합한 업데이트다.

**가장 중요한 원칙은 기존 기능과 데이터의 정확성을 100% 보존하는 것이다. 기능을 단순화하거나 삭제해서 성능을 개선해서는 안 된다.**

## 0. 구현 전 전체 코드 감사

먼저 최신 `main`과 로컬 working tree, 커밋 상태를 확인한다. 사용자의 미커밋 변경 사항을 삭제하거나 덮어쓰지 않는다.

기존 v2.6.6에서 구현된 기능, 공식 계산 구조, 캐시, 가상화, 지연 렌더링, 데이터 저장 흐름을 충분히 분석한다.

특히 다음 파일과 관련 코드를 확인한다.

- `CompetitionScreen.tsx`, `StandingsTable.tsx`, `StandingsScreen.tsx`
- `cupTable.ts`, `competition.ts`, `competitionSelectors.ts`, `seasonAnalytics.ts`
- `PlayerDetailScreen.tsx`, `MatchDetailScreen.tsx`
- `NewMatchScreen.tsx`, `EditMatchScreen.tsx`
- `App.tsx`, navigation 및 screen-state 관련 모듈
- Records, Awards, News, Team History 및 성능 측정 코드
- Store, IndexedDB, Supabase 동기화 및 match validation 코드

기존 공통 컴포넌트와 source of truth를 재사용하고, 중복 계산이나 데이터 불일치를 유발하는 구조부터 확인한다.

기존 성능 최적화가 적용되어 있는 부분은 무분별하게 재작성하지 않는다. 실제 병목과 회귀 위험이 확인된 부분부터 수정한다.

## 1. Player Detail — 화면 분리 및 성능 개선

현재 하나의 긴 화면에 표시되는 Player Detail을 두 개의 화면 또는 탭으로 구분한다.

권장 구성:

**Overview**
- 기존 선수 프로필, 핵심 통계 및 순위
- Recent Form
- Rank Trend
- Active Streaks
- 공식 개인상과 Career Awards
- 포지션별 기록 및 기존 세부 분석
- 기타 기존 Overview의 고유 기능

**Matches**
- 선택한 시즌·대회의 전체 출전 경기
- 기존 경기별 평점, 득점, 도움, 출전시간 및 상세 기록
- 경기 선택 시 기존 Match Detail로 이동
- 기존 경기 정렬 및 필터 의미 유지

최근 경기 접근성을 높이되, 기존 화면의 정보와 기능이 삭제되어서는 안 된다.

Overview와 Matches를 구분하면서 선택한 탭에서 필요하지 않은 고비용 계산은 수행하지 않도록 한다.

기존 시즌·대회 필터, 포지션별 순위, 역사적 소속팀 스코프, 개인상, 이적 및 방출 선수 처리를 유지한다.

화면을 이동했다가 돌아올 때 탭·필터·스크롤 복원도 기존 navigation 구조에 맞게 처리한다.

## 2. Back 버튼 개선

현재 상세 화면은 아래로 스크롤하면 상단 Back 버튼에 접근하기 어렵다.

Player Detail 및 관련 상세 화면에서 필요한 Back 버튼을 스크롤 중에도 접근할 수 있도록 개선한다.

- 기존 Back 버튼의 시각적 디자인과 앱 UI를 최대한 유지한다.
- Sticky 방식 또는 기존 내비게이션 구조를 활용해 가장 안정적인 구현을 선택한다.
- 화면 내용을 가리거나 스크롤 영역을 불필요하게 줄이지 않는다.
- 모바일 safe area, 하단 내비게이션, Scroll-to-Top과 충돌하지 않는다.
- 기존 navigation history, 이전 화면, 스크롤 복원 기능을 유지한다.
- 뒤로 가기 중 화면이 중복 생성되거나 이전 상태가 사라지지 않도록 검증한다.

여러 화면에서 동일한 문제를 해결해야 한다면 공통 컴포넌트로 처리하되, 관계없는 페이지의 디자인까지 변경하지 않는다.

## 3. Edit Match — 기존 경기 정보 수정 기능 확장

현재 경기 수정 기능은 기존 경기의 기록 수정에 집중되어 있으며, 경기의 대회 식별 정보는 저장된 assignment에 의해 제한된다.

기존 경기 수정 화면 상단의 **대회·경기 정보 및 스코어 박스**를 누르면 경기 정보 수정 기능에 접근할 수 있도록 한다.

수정 대상은 안전하게 지원 가능한 범위에서 다음과 같다.

- Competition Type: League / Cup / Champions
- Season
- Matchday 또는 해당 대회의 Stage
- 경기 날짜
- 대진 및 상대팀 정보
- 기타 기존 경기 정보와 연관된 필드
- 스코어 수정은 골 이벤트 및 기존 기록의 정합성을 유지하는 방식으로 지원

특히 **Champions 경기로 저장한 기록을 League 경기로 변경**하는 사례가 올바르게 작동해야 한다.

다음 사항을 반드시 검증한다.

1. 기존 Match ID, 선수 기록, 이벤트 ID, 출전시간 및 교체 기록 보존
2. 변경한 대회에 맞는 canonical competition assignment 생성
3. 기존 대회와 변경된 대회의 통계·진행도·순위 업데이트
4. 공식 개인상, 팀 기록, Records 및 History 재계산
5. 기존 Cup/Champions 진출·탈락·대진 규칙 및 후속 경기와의 충돌 방지
6. 중복 Matchday 및 잘못된 Stage assignment 방지
7. 저장 취소·실패 시 기존 데이터 보존
8. IndexedDB 및 Supabase 동기화 안전성

현재 Editor의 `frozenAssignment` 및 `activeEditorIdentity` 구조를 검토하고, 기존 안전장치를 단순히 제거하는 방식으로 구현하지 않는다.

경기 정보 수정과 선수 이벤트 수정의 책임을 명확하게 구분하되, 기존 편집 UX와 저장 경로를 재사용한다.

스코어를 독립적인 임의 숫자로만 바꿔 경기 이벤트 및 기록과 불일치하게 만드는 방식은 금지한다.

기존 기록이나 후속 토너먼트 진행과 충돌해 안전하게 수정할 수 없는 경우에는 저장을 차단하고 명확한 사유를 표시한다. 기록을 묵시적으로 삭제하거나 자동 보정하지 않는다.

## 4. League & Cup — 테이블 정렬 기능

리그와 컵의 팀 순위 테이블 모두에 헤더 클릭 정렬을 구현한다.

### 공통 규칙

- 기존 UI에서 헤더 텍스트 자체를 누르면 정렬
- 별도의 정렬 버튼이나 툴바 추가 금지
- 첫 번째 클릭은 해당 통계의 기본 방향
- 두 번째 클릭은 반대 방향
- 다른 통계 선택 시 해당 통계의 기본 방향으로 전환
- 왼쪽 공식 순위 `#` 클릭 시 원래 순서로 복원
- 동률인 경우 해당 테이블의 원래 공식 순위를 tie-break로 사용
- 실제 공식 순위와 모든 통계 데이터는 절대 변경하지 않음
- 배열 정렬은 별도의 presentation projection에서 수행
- 원본 순위 배열에 대한 in-place sort 금지

기본 정렬 방향:

| Header | 첫 클릭 |
|---|---|
| P | 내림차순 |
| W | 내림차순 |
| D | 내림차순 |
| L | 오름차순 |
| GF | 내림차순 |
| GA | 오름차순 |
| GD | 내림차순 |
| Pts | 내림차순 |

### 반드시 보존할 UI

**리그 테이블의 기존 가로·세로 크기, 컬럼 너비, 행 높이, 글자 크기, 간격, 색상 및 디자인을 유지한다.**

현재 실제 코드에서는 `GF-GA`가 하나의 컬럼이다. 이를 억지로 두 컬럼으로 분리해 테이블을 넓히지 않는다.

`GF-GA` 영역 내의 `GF`와 `GA`를 각각 클릭할 수 있도록 하되, 기존 외형과 컬럼 너비를 유지한다.

정렬 방향을 나타내는 표시가 필요하다면 기존 레이아웃에 영향을 주지 않는 최소한의 표시만 사용한다.

기존 `#`, `Team`, `P`, `W`, `D`, `L`, `GF-GA`, `GD`, `Pts`의 시각적 표기와 순서를 기준으로 삼는다.

정렬은 League Overall과 Form 등 해당 테이블이 사용되는 기존 조회 경로에서 작동하도록 한다.

정렬이 적용되어도 왼쪽에 표시되는 순위는 해당 조회 범위의 원래 공식 순위를 그대로 보여준다.

스테이지·시즌·테이블 모드 등 조회 범위가 바뀌면 이전 범위의 정렬 상태가 새 범위에 잘못 적용되지 않도록 한다.

## 5. Cup Table — 리그 디자인 기반으로 통일

이번 작업의 핵심이다.

**리그 테이블을 시각적인 Reference UI로 사용하되, Cup 테이블 고유의 구조와 기능은 모두 유지한다.**

### 리그 스타일에서 가져올 요소

- 팀 이름 및 전체 이름 표기 방식
- 팀 로고 크기와 배치
- 테이블 배경 및 테두리
- Header 글자 크기·굵기·색상
- 데이터 글자 크기·굵기·정렬
- 행 높이와 기본 간격
- 순위·승점·득실차의 강조 방식
- 팀 클릭 인터랙션

가능하면 `StandingsTable`, `TeamLink`, `TeamIcon` 등의 기존 공통 표현을 재사용한다.

다만 Cup 기능 때문에 필요한 추가 정보가 없어지지 않도록 한다.

현재 Cup 테이블의 `W-D-L`, `GF-GA` 복합 영역은 기존 전체 너비를 유지하면서 개별 지표를 클릭해 정렬할 수 있게 설계한다.

### 절대 삭제하면 안 되는 Cup 고유 기능

- Survival Line
- Provisional Survival Line
- At Risk
- Surviving
- Eliminated
- Not Played
- Champion
- Runner-up
- Stage별 순위와 통계
- Total 통계
- 진출 및 탈락팀 상태
- 상태별 색상 및 강조
- 동률팀 처리와 Elimination Draw
- Final Replay 관련 알림
- 팀 선택 및 이동
- 컵 진행도와 이전 스테이지 기록
- 아직 경기를 하지 않은 팀과 이미 탈락한 팀의 구분

이 정보들은 리그 UI에 추가되는 Cup 전용 요소로 취급한다.

**Survival Line은 특히 주의해야 한다.**

공식 순서에서는 기존과 동일한 위치와 의미로 표시한다.

GF, Pts 등 통계 기준으로 정렬할 때는 경계선이 새로운 행 순서에 잘못 적용되지 않도록 한다. 이 경우에도 원래 생존 경계 및 상태 정보를 명확하게 유지할 수 있는 비위치형 표시를 제공한다.

정렬 때문에 실제 진출·탈락 상태가 바뀐 것처럼 보이는 UI는 금지한다.

Stage의 진출 판정과 Official Rank는 기존 엔진 결과를 그대로 사용한다.

컵 UI의 상태별 부가 텍스트로 인해 필요한 행 높이는 유지하되, 모바일에서 잘림·겹침·가로 스크롤이 새로 발생하지 않도록 한다.

## 6. 앱 전체 렉·딜레이 최적화

기능 구현과 별도로 주요 화면의 병목을 측정하고 개선한다.

우선 검토 대상:

### A. Standings / League History
- `StandingsScreen`의 전체 시즌 분석 호출
- League Overall의 불필요한 History 생성
- 현재/이전 Matchday 스냅샷 재사용
- 순위 헤더 클릭 시 공식 순위 재계산 방지

### B. Cup Stage
- `cupTableModel`의 이전 스테이지 조회
- `cupCompetition` 반복 파생
- 스테이지별 캐시 재사용
- 클릭 시 정렬만 필요한 경우 기존 계산 결과 재사용

### C. Player Detail
- 화면 분리에 따른 조건부 계산
- Career Timeline 및 Personal Records
- Chemistry
- Rank Trend
- Match History
- 화면 재진입 시 데이터 재사용

### D. Match Editor
- 입력 상태 변경 시 불필요한 전체 화면 계산
- 선발·벤치 렌더링
- 이벤트 입력 및 선수 선택
- 경기 정보 변경 이후 재계산 범위
- 기존 자동 저장 및 저장 검증에 미치는 영향

### E. Records / Awards / News
- 대량 기록 조회의 최초 계산 시간
- 공식 개인상과 Season Best XI
- 경기 수정 후 캐시 무효화
- 선택하지 않은 기록 카테고리의 불필요한 계산
- 기존 지연 로딩과 가상화 유지

### F. 앱 초기 로딩
- `App.tsx`의 정적 화면 import 구조
- 필요 시 route-based code splitting 검토
- JS 초기 로딩과 실행 비용
- IndexedDB 복원 및 PWA 서비스 워커 호환성

**무조건 최적화하지 않는다. 반드시 먼저 측정하고 실제 개선 가능성과 회귀 위험을 비교한다.**

이미 빠른 캐시 경로를 다시 구현하거나, 성능 개선을 위해 결과 계산을 생략해서는 안 된다.

## 7. 성능 측정 및 검증

기존 약 367명·1,152경기·2시즌 규모의 성능 테스트 데이터를 재사용한다.

가능하면 더 큰 데이터에서도 확장성을 확인한다.

변경 전후로 다음을 측정한다.

- 앱 최초 로딩 및 첫 화면 렌더링
- 리그·컵 테이블 진입
- 순위 정렬 및 원래 순위 복원
- 과거 Cup Stage 전환
- League History 진입
- Player Detail 최초 진입 및 재진입
- Overview / Matches 전환
- Match Editor의 입력 반응성
- Records 및 Awards 최초 계산
- 기존 경기 수정 후 통계 재계산

최초 계산과 캐시 적용 후 계산을 분리해 보고한다.

median 및 p95, 적용 가능하면 렌더링 비용과 메모리도 비교한다.

측정 결과가 불안정하거나 개선이 확인되지 않는 변경은 되돌리고 기존 구조를 유지한다.

캐시 추가 시에는 메모리 증가, 잘못된 재사용, 데이터 수정 후 오래된 결과를 반환하는 문제가 없는지 확인한다.

## 8. 정확성 및 회귀 테스트

다음 사항을 필수 검증한다.

**공식 기록 정확성**
- Rating REV13 유지
- 기존 평점식, MOM, 개인상 및 Best XI 정책 유지
- 경기 이벤트와 출전시간 계산 유지
- 기존 출전시간 90분 제한 유지
- 순위·승점·동률 판정 유지
- 리그·컵·챔피언스 진행 규칙 유지

**경기 수정**
- League ↔ Cup ↔ Champions 변경
- 경기 정보 수정 전후 데이터 정합성
- 후속 컵 대진이 존재하는 경기의 수정 검증
- 과거 이적·방출 선수와 누락된 선수 ID
- 중복 경기 및 잘못된 Competition Assignment
- 저장 실패와 복원, 오프라인 저장 및 동기화

**테이블**
- P/W/D/L/GF/GA/GD/Pts 각각 양방향 정렬
- 동률에서 공식 순위 우선
- 공식 순위 숫자 보존
- `#`를 통한 원래 순서 복원
- League Overall/Form
- Cup Total/각 Stage
- At Risk, Eliminated, Surviving 및 Not Played 표시
- Survival Line/Provisional Survival Line
- Final Replay와 Champion/Runner-up
- 팀 상세정보 이동

**UI**
- 기존 테이블 크기 및 레이아웃 보존
- 컵과 리그의 공통 스타일 일관성
- 320px, 375px, 390px 모바일 화면
- 클릭 영역과 키보드 접근성
- Back, Scroll-to-Top, 스크롤 복원
