# Football Tracker v2.5.11 릴리스 보고서

기준: `c278609c65660a6aa915aa1b7210461994512992` (v2.5.10). 작업 시작 시 main의 working tree는 clean이었다. 요청서에 지정된 조회 화면 개선과 렌더링 최적화를 구현했다.

주요 변경 파일은 `PlayerDetailScreen.tsx`, `TeamDetailScreen.tsx`, `GlobalRankingScreen.tsx`, `VirtualRankingList.tsx`, `rankingWindow.ts`, `competitionOptions.ts`, `App.tsx`, `types.ts`, `navigation.ts`, `lastRoute.ts`, `Pitch.tsx`, `ui.tsx`다. package·lock·config와 기존 버전 assertion을 2.5.11로 맞췄고, `v2511-*` 회귀·동등성·측정 파일과 증빙 문서를 추가했다.

## Player Detail

Positions Played는 출전시간이 양수인 정규화 포지션을 모두 표시하고 출전시간 내림차순으로 정렬한다. 비율은 소수 첫째 자리로 표시하며 반올림하면 0.0%가 되는 양수 비율은 `<0.1%`로 표시한다. 설명은 `Match-position timeline minutes · all played positions.`로 변경했다. 기존 `derivePlayerScope`와 공식 timeline 분모·출전시간·정규화는 유지한다.

10% 미만, 1% 미만, 극소 비율, 0분·미출전, LAM/RAM 합산, 시즌·대회 분리와 빈 스코프를 행동 테스트로 검증했다. 과거 10% cutoff를 요구하던 assertion은 새 동작으로 변경했고 기존 HTML 전체 비교는 승인된 설명·비율 정밀도 변경만 정규화한다.

## Team Detail Players

Player Detail과 같은 `RankingMetricTabs` 및 공통 `COMPETITION_OPTIONS`를 사용한다. 기본 metric 크기·색·간격·가로 스크롤·선택 항목 자동 표시를 공유한다. 화면 순서는 대회 버튼 → Latest XI → Bench → Roster Management다. Import Squad 동작과 디자인은 유지한다.

`playersCompetition`을 Team 화면 전용 상태로 추가했다. Overview/Matches와 독립이며 탭 변경, 선수 상세 Back, 마지막 화면 저장·복원에 포함된다. v2.5.10 저장 화면 상태에 필드가 없거나 잘못된 값이면 All로 복원한다. 선수 상세 이동에도 현재 시즌·대회를 명시한다.

Latest XI는 대회만 필터링한 뒤 기존 `teamBestEleven`을 호출한다. 해당 함수의 기존 시즌·recorded-team·최신 경기 정렬·킥오프 선택·저장 포메이션·좌우 전술 위치·좌표·ID를 재사용한다. 시즌 Best XI나 교체 후 배치를 사용하지 않는다.

현재 로스터와 과거 선발 선수의 합집합에 `playerSeasonStats(player, players, matches, season, teamId, competition)`을 적용한다. 선발과 Bench의 평균 평점·골·어시스트가 모두 같은 시즌·대회·기록 당시 팀 기준을 따른다. All 평균은 각 경기 공식 raw 평점의 평균이다. 출전하지 않은 선수는 평점 `—`, 골·어시스트 0이다. 공용 Pitch/Bench의 기본 빈 평점 표시는 유지하고 Team에서만 선택적 `emptyRatingLabel`을 지정한다.

Bench는 현재 팀 등록 선수 중 선택한 Latest XI에 없는 선수다. 과거 이적·방출 선발은 과거 XI에 남지만 현재 Bench에 재등록되지 않는다. 경기 없는 대회에는 `No match data yet`와 현재 전체 로스터 Bench를 표시한다. 현재 로스터에 없는 역사적 ID도 킥오프 슬롯에서 보존하며, 계산할 선수 정보가 없는 평점을 임의 생성하지 않는다.

대회 4종의 XI·좌표·선발/Bench 통계, 다른 recorded-team 경기 배제, 이적 선수, 미출전·빈 대회, 대회별 경기 수가 다른 평균, Import Squad, route 저장·복원·Back을 검증했다.

## Global Ranking 병목 및 구현

기존 화면은 canonical 결과 전체에 `RankingRow`를 생성한다. 통계 facts와 정렬에는 이미 참조 기반 캐시가 있고, 동일 metric 재선택은 같은 결과 객체를 반환한다. 따라서 공식 통계 엔진을 변경하지 않았다.

`VirtualRankingList`와 `rankingWindow`를 추가했다. 실제 `.app-content`의 높이와 목록 위치, 렌더된 행의 자연 높이를 측정한다. 초기 행 높이 추정은 기존 min-height 52px + border 1px이며, mount/ResizeObserver에서 실제 높이로 교정한다. 행은 기존 디자인을 사용하고 6행씩 overscan한다. 전체 높이는 앞뒤 spacer로 유지하고 전체 canonical rows는 그대로 보유한다. 안정적인 playerId 키와 전체 순위의 절대 index를 사용한다.

별도 세로 스크롤 영역은 만들지 않았다. native scroll을 passive listener로 관찰하고 프레임당 한 번만 갱신한다. ResizeObserver는 viewport·목록·측정 행을 관찰하며 observer·listener·예약 프레임을 해제한다. 목록 크기가 줄어들면 범위를 즉시 보정하고 브라우저의 scroll clamp 뒤 발생하는 scroll/resize를 반영한다. metric 전환에서 scrollTop을 직접 초기화하지 않는다. 기존 Scroll to Top 및 App의 Back 복원 로직을 재사용한다.

`App.tsx` 시즌 목록은 matches/competitionStates 참조가 달라질 때만 재계산한다. `RankingMetricTabs`는 value 변경 때만 위치를 읽고 이미 보이는 버튼에는 scrollLeft를 쓰지 않는 기존 동작을 유지한다. 가상화로 DOM 규모를 줄여 공통 탭·사진·로고 컴포넌트에 추가 캐시나 별도 스타일을 도입하지 않았다. 새 의존성은 없다.

League analytics는 최초 진입에서 별도 비용이 있으나 metric 전환에서는 기존 useMemo/공통 캐시를 재사용한다. 포지션 필터에서는 movement가 원래 숨겨지므로 analytics 계산도 생략한다. 팀 필터의 기존 생략 규칙을 유지한다. 표시하는 League movement는 기존 canonical snapshot과 `rankingMovement`를 그대로 사용한다. 월간 수상·League 전체 분석 알고리즘은 변경하지 않았다.

## 성능 측정

최종 수치는 [ranking 측정 JSON](../performance/v2.5.11-ranking.json)에 기록한다. baseline/current 독립 소스 그래프, 같은 합성 이력 367명·1,152경기, production React, 7회 교대 측정이다. 표본 전체·중앙값·p95와 대회별 최초 선택/재선택을 보존한다. 합성 이력에서 실제 qualifying 랭킹은 191명이다. 순수 window 검증은 350명 전체·마지막 행 도달도 별도로 검사한다.

초기 development React 측정은 JSX owner-stack 진단 비용이 render callback 안에서 반복되어 SSR 반복 비용이 왜곡됐다. CPU profiler에서 development JSX 함수가 주 비용임을 확인한 뒤 양쪽 모두 production React로 다시 측정했다. 테스트/build와 겹친 중간 실행은 최종 성능 근거로 사용하지 않고, 최종 실행은 단독 수행한다.

DOM 수는 React SSR에서 생성한 구조를 센 값이다. 실제 브라우저의 live DOM·commit·layout·paint·long task·FPS·터치 입력 지연과 동일한 측정이 아니다. `cua.getState()` 결과 apps와 browsers가 모두 비어 브라우저 Profiler/실기 측정을 수행하지 못했다.

## 정확성 및 품질

독립 v2.5.10 baseline과 2시즌 × 4대회 × 전체/팀/9포지션 필터 × 모든 공식 metric 및 goalsConceded의 전체 facts·순서가 일치한다. 캐시 재사용과 입력 불변성도 확인한다. REV13·timeline·stats·seasonAnalytics·competition·awards·kickoffLineup·repository·validation·rankingMetrics·store 소스는 줄바꿈을 정규화한 뒤 기준 버전과 동일함을 검사한다.

기존 1,025개 테스트를 유지하고 새로운 회귀 테스트를 추가했다. 가상 목록은 top/middle/end, 실제 viewport 크기 변화, 소수 행 높이, 빠른 scroll 합치기, 마지막 선수 클릭, metric 순서 변경 시 위치 유지, 짧아진 목록, 복원 위치에서 mount, Scroll to Top과 같은 offset 복귀, cleanup을 DOM 모형으로 검증한다.

독립 리뷰어가 전체 diff와 최종 변경분을 두 차례 검토했으며 치명적·중요 결함을 발견하지 못했다. 실제 browser effect 순서·scroll clamp·Back 복원은 DOM 모형과 정적 리뷰의 한계로 명시했다.

- `npm.cmd test`: **1,050/1,050 통과**, 실패·skip 0. 기존 1,025개 + 신규 25개. 최종 소스 diff 검토에서 원복한 기존 포지션 필터 assertion은 해당 파일 9/9 재검증했다.
- `npm.cmd run lint`: 오류 0, 기존 경고 **43→43**, 신규 경고 0. 중간에 신규 테스트의 unused destructuring 경고 4개를 수정했다.
- `npm.cmd run build`: TypeScript 및 Vite production build 성공.
- `git diff --check`: exit 0. Git의 CRLF 변환 안내는 whitespace 오류와 구분했다.
- 동일 의존성·환경으로 기준 커밋을 직접 빌드한 [quality 비교](../performance/v2.5.11-quality.json): JS **937,014→939,549 bytes** (+2,535), gzip **262,695→263,551 bytes** (+856). DOM 가상화·상태·빈 평점 표시에 필요한 코드 비용이며 번들 축소로 보고하지 않는다.
- 버전 **2.5.11**, Rating Revision **REV13**. 검증 명령과 범위는 [verification 증빙](../performance/v2.5.11-verification.json)에 기록한다.

사용자 실제 저장 데이터를 읽거나 재작성하는 migration은 실행하지 않았다. 저장 키 `football-tracker-v1`, DB 버전, Draft, Backup/Import, Retry, PWA/Offline, Cloud Sync 비활성화 정책을 유지한다. 기존 500kB chunk 크기 경고는 계속 존재한다.

## 남은 검증 한계

실제 모바일 스와이프·빠른 스크롤·화면 회전·하단에서 작은 결과로 전환하는 native scroll clamp·상세 이동 후 browser Back 복원·브라우저 heap·PWA offline 실기는 미검증이다. SSR 개선을 모바일 FPS나 입력 지연 개선 수치로 주장하지 않는다. 필터 없는 League 최초 analytics 계산 비용은 그대로 남는다. 전체 선수 접근·터치 이벤트 연결·복원 controller는 기능 테스트와 정적 검토를 수행했다.
