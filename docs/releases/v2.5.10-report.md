## 2. 유지한 공식 규칙과 데이터

- Rating Engine REV13의 모든 계수·포지션 변경·MOM·tie-break 유지.
- Positions Played는 기존 canonical 실제 구간을 정규화해 합산한다. LAM/RAM→CAM, 좌우 계열 구분 및 10% 미만 숨김 유지.
- 공식 출전시간은 최대90분. 추가시간 이벤트와 원본 경기 duration은 별개로 보존.
- League/Cup S1~S7/Survival Line/At Risk/Eliminated/Final/Replay/Champions 판정 및 모든 수상·Records·Chemistry·News·Latest Changes 유지.
- 저장 키 football-tracker-v1, DB 버전2, 저장 스키마·primary 검증 read-back·IndexedDB mirror·backup·atomic Import·450ms Draft·PWA 정책 유지.
- 과거 Match의 playerId를 현재 선수 ID로 대체하지 않으며, 등록 선수 삭제를 복구한다는 이유로 공식 데이터에 가상의 선수를 넣지 않는다.

저장된 과거 이름·사진 snapshot 필드가 현재 스키마에는 없다. 삭제된 선수의 원래 이름·사진을 추측하지 않는다. 현재 Player 객체가 남아 있는 방출·이적 선수는 실제 객체를 그대로 표시한다. 과거 ID만 있는 선수의 공식 평점·MOM을 새로 만들어 제공하지 않는다.

## 4. 저장 결과와 복구

일반 API는 기존 동기 mutation 인터페이스를 유지한다. 화면 이동 후에도 저장 실패 안내가 StoreProvider에서 유지되고, 재시도는 현재 가장 최신 snapshot을 저장한다. primary 검증이 실패하면 Cloud 변경 큐에 전달하지 않는다. mirror 실패나 Cloud 네트워크 오류는 이미 검증된 local primary 성공을 취소하지 않는다.

StrictMode updater 재실행, 빠른 연속 수정, 경기 삭제와 즉시 이동, Draft 취소·최종 저장, quota/접근 예외, 실패 뒤 다른 수정·재시도, Import rollback과 진행 중 수정/최종 저장, Squad Import batch 재시도를 검사했다. 원본 사용자의 localStorage/IndexedDB 대신 메모리 저장소 및 테스트용 DB 경계를 사용했다.

현재 production Cloud Sync flag는 false다. 활성화 경로의 기존 syncNow는 네트워크 pull 이후 오래된 merge를 primary에 쓸 수 있어 별도 rollout 전 동시성 보강이 필요하다. 이 릴리스는 Cloud 서버·인증·프로토콜 또는 flag를 변경하지 않았다. Cloud 오류 검사는 mock 경계이며 실제 서버 통합 검증은 아니다.
