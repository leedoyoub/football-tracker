### 유지한 표시 차이

- Team Detail Bench는 현재 로스터에서 Latest XI를 뺀 목록이고, Match Detail Bench는 해당 경기의 저장 appearance 목록이다. 서로 다른 의미의 목록을 통일하지 않았다.
- Team Detail Bench의 정렬은 `src/lib/positionOrder.ts:4`의 GK→수비→중원→공격 순서다. Match Detail Bench는 `src/screens/MatchDetailScreen.tsx:26`, `src/screens/MatchDetailScreen.tsx:78`의 기존 공격→중원→수비→GK 순서를 사용한다. 후자의 정렬 키는 저장 appearance.position이며, 실제 투입 포지션 라벨과는 별개다. 기존 정렬과 라벨을 이번 감사에서 바꾸지 않았다.
- Team Detail Bench는 전체 커리어 대표 계열을 사용한다. 선택 시즌의 Best Players 라벨과 다를 수 있으나 현재 로스터 관리 화면의 기존 정책이다. 이를 시즌 통계의 잘못된 분류라고 단정하지 않았다.

## 실행으로 확인한 결과와 legacy 차이

입력: 현재 B팀의 p(등록 CM), r(등록 CAM)가 Season 1의 A팀 경기에서 둘 다 CAM으로 90분 출전. r은 20분에 득점한다. 아래 코드는 저장소 루트의 Node에서 `tests/helpers/register-ts.cjs`를 먼저 require한 뒤 실행한 실제 입력이다.

```js
const players = [
  { id: 'p', name: 'Target', position: 'CM', teamId: 'B', teamIds: ['B'], number: 1 },
  { id: 'r', name: 'Rival', position: 'CAM', teamId: 'B', teamIds: ['B'], number: 2 },
]
const match = {
  id: 'm', season: 'Season 1', matchDay: 1, date: '2026-01-01',
  teamId: 'A', homeTeamId: 'A', awayTeamId: 'O', duration: 90,
  appearances: players.map(p => ({
    playerId: p.id, teamId: 'A', role: 'starter', position: p.position, matchPosition: 'CAM',
  })),
  events: [{ id: 'g', type: 'goal', minute: 20, teamId: 'A', playerId: 'r' }],
}
```

| 실제 호출 | 관측 결과 |
| --- | --- |
| `rankGlobalRankingRows(buildGlobalRankingData(players, [match], { seasons: ['Season 1'], teams: ['A'], positions: ['CAM'] }, 'rating'), players, 'rating')` | r, p 순서. 두 row 모두 current teamId=B, historicalTeamId=A, scopedPositionFamily=CAM. 현재 등록 CM인 p도 누락되지 않는다. |
| `scopedMetricRanks(rows, players, 'p', scopedPositionFamilyByPlayer(players, [match], { teams: ['A'] }))` | overall=2, position=2, team=2. |
| `awardCandidatesForScope(players, [match])` | r, p 모두 teamId=A 및 family=MID. 현재 B팀이나 등록 CM/CAM을 역사 팀 대신 사용하지 않는다. |
| `getLeaderboard(players, [match], { seasons: ['Season 1'], teams: ['A'], positions: ['CAM'] }, 'rating')` | r만 반환. 등록 CM인 p는 제외되는 legacy 차이 재현. |
| `scopedPlayerRanks(rows, players, 'p').position` | 1. canonical의 2와 다른 legacy 등록 포지션 분류를 재현. |
| `bestEleven(players, [match], 'Season 1')` | r→LCM, p→CM. legacy 등록 포지션 pool 배치임을 재현. |

확인된 차이는 호출이 없는 legacy API의 동작이다. 이번 추가 감사 범위에서 새로 수정해야 한다고 입증한 production 포지션/역사 팀 스코프 오류는 없다. 위 제한된 입력과 호출 경로를 확인한 결과이며, 앱 전체의 무오류를 보증하는 의미는 아니다.
