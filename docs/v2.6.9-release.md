# Football Tracker v2.6.9

기준 커밋은 `6be9bf45d08983cb6f37003f7c9685981abda3c7` (v2.6.8)이다. 최초 구현 시작 당시 로컬과 GitHub main이 같았고 미커밋 변경은 없었다. 2026-11-13 중단 작업 복구 시에는 main 위의 v2.6.9 구현·테스트·문서가 미커밋 상태였고, 원격 main과 마지막 성공한 Pages 배포는 여전히 v2.6.8이었다. 기존 파일을 초기화하거나 재작성하지 않았다.

## Player Detail

Matches의 공식 MOM 평점을 기존 `text-blue-300`과 `★`로 강조한다. `getMatchManOfTheMatch(match, players)`의 기존 경기별 캐시를 사용하며 평점 숫자, 소수점, 일반 경기 색상과 Rating Details를 유지한다. 원본 경기 교체 후에는 기존 공식 캐시 무효화 경로가 적용된다.

Recent Form에서 중복된 최근 5경기 버튼만 제거했다. 그래프, 경기별 평점, Last 5 avg·Season avg·Trend 및 가로 스크롤은 유지한다. SVG 점과 숫자가 경기 ID에 직접 연결되고 Enter/Space로 활성화된다. 포인터 이동·취소와 실제 가로 스크롤 뒤의 클릭을 차단하며 SVG/가로 스크롤의 기존 Swipe Back 제외 규칙을 사용한다.

## 순위와 필터

Global Ranking·Award Race·Records 선수 기록·Records Leaderboard는 다음 순서로 처리한다.

1. 시즌·대회 범위의 전체 공식 사실을 계산한다.
2. 선택한 포지션 그룹을 OR 합집합으로 만들고 기존 화면별 정렬·동률 정책에 따라 순위를 정한다.
3. 선택 팀은 역사적 출전 팀 ID의 OR 표시 필터로 적용한다. 포지션과 팀 사이는 AND다.
4. 표시 행의 인덱스로 순위를 다시 매기지 않는다. 팀을 선택하면 순위에 빈 번호가 생길 수 있다.

Global Ranking의 팀 변경은 공식 집계·정렬과 분리한다. 포지션은 선택 범위의 대표 포지션과 기존 정규화 규칙을 사용한다. Award Race는 공식 후보·점수·최고 후보 선택 및 동률 순서를 유지한다. 선수 수상 Records는 기존 수상 이벤트의 포지션 의미를 유지하며 팀 선택으로 전체 수상 횟수를 줄이지 않는다. 팀 자체 순위, Team Detail의 팀 내부 Best Players와 조합 기록의 집계 의미는 유지한다.

Home에는 포지션 필터만 있고 대회 기본 선수 순위에는 팀·포지션 동시 선택이 없다. 해당 경로는 기존 공식 정렬을 유지한다. 팀 내부 순위를 전역 순위로 바꾸지 않았다.

기존 CompactMultiFilterMenu의 시즌 선택 API를 보존하면서 옵션 ID/표시 이름을 지원하도록 확장했다. 단일 선택은 `menuitemradio`, 복수 선택은 `menuitemcheckbox`를 사용한다. 복수 선택 팝업은 선택마다 닫히지 않으며 외부 클릭·Escape·Tab으로 닫힌다. 방향키/Home/End와 Escape 후 트리거 포커스를 유지한다. All/All teams와 빈 배열은 전체 범위다. 단일 선택 버튼에는 이름, 여러 선택에는 Position (N)/Team (N)을 표시한다.

새 배열 필드는 기기별 ScreenState에만 추가한다. 구버전 단일 필터를 읽고 `fb`는 `lb-rb`로 정규화하며 중복·잘못된 포지션·존재하지 않는 팀 ID를 제거한다. Records View All에도 모든 선택을 전달한다. 축구 데이터 저장 스키마와 동기화 큐는 변경하지 않는다.

## 계산 최적화

선수 Records의 전체 카탈로그에서 경기별 골 분류를 한 번 공유하고 기존 평점 사실에서 연속 기록을 계산한다. 단일 리더보드에는 요청 ID를 전달해 다른 그룹의 MOM·수비·골 분류·정렬을 생략한다. 지표·포지션 전환에는 기존 소스 범위의 기록 사실을 재사용하며 팀 변경에는 완성된 순위만 필터링한다.

`combinationStats`는 한 번의 경기·팀 조회에서 같은 선수의 공식 출전 구간을 반복 탐색하지 않는다. 이 구간 재사용은 Recap에도 적용된다. 전체 캐시 구조를 교체하거나 공식 출전 조건·분모·동률을 바꾸지 않는다. `unitRecords`의 점수·골·실점 자격·SOT 선계산은 helper 호출을 줄였지만 단일 조합 조회와 수정 후 조회를 악화시켜 제거했다. 원래 v2.6.8 엔진과 캐시를 그대로 복원했고 byte 동일성 검사도 유지한다. 제거한 구현의 원시 측정은 `v2.6.9-records-rejected.json`에 남긴다.

News와 Latest Changes에서는 이미 적용된 시즌별 캐시와 공식 개인상 공유 외에 추가로 줄일 중복이 확인되지 않아 코드를 유지했다. 실제 측정에서 이득이 없는 경로는 개선으로 보고하지 않는다. Home 지연 시점, Store 구조, 가상 목록, 초기 JS 분할은 변경하지 않는다.

## 검증 방법과 범위

독립 v2.6.8 소스를 git archive로 추출하고 현재 코드와 분리된 모듈 그래프에서 같은 합성 fixture를 실행한다. 2시즌 1,152경기·6시즌 3,456경기와 367명 원본 fixture를 사용한다. CPU 측정은 작업별 독립 프로세스에서 기준/현재 순서를 번갈아 실행하며 모듈 변환·fixture 생성·명시적 GC를 타이밍에서 제외한다. 중앙값과 p95 및 원시 표본을 JSON에 보관한다. 엔진 CPU, production SSR, 실제 브라우저 프레임을 구분한다.

공식 결과 비교는 모든 Records 그룹·개별 리더보드·raw UnitRecord, News 이벤트 필드·순서·선택 옵션, Latest Changes, Recap·Starting XI·조합 결과를 포함한다. 과거 경기 수정·삭제·추가, 이적·방출·중복 ID와 완료 상태도 비교한다. 의도적으로 변경된 선수 팀 필터는 기준 버전의 전체 순위를 역사적 팀으로 투영한 결과와 비교한다.

6시즌 원본 JSON은 기존 Chromium localStorage 용량 한계를 초과하므로 브라우저에서는 2시즌 fixture를 사용한다. 6시즌 CPU/SSR 데이터를 임의로 줄이거나 저장소 quota를 우회하지 않는다. 물리적 iPhone/Safari·Android·실제 사용자 DB 쓰기 검증을 의미하지 않는다.

## 회귀 검증과 감사

unit 선계산을 제거한 최종 코드로 전체 자동화 테스트를 다시 실행해 **1,371/1,371 통과**, 실패·취소·건너뜀 0건을 확인했다. TypeScript 및 production build가 통과했고 lint는 종료 코드 0, 오류 0건, 경고 44건이다. 이전 기록의 43건 이후 추가된 Player 브라우저 하네스의 `no-unsafe-finally` 경고 1건을 포함한 실제 최종 결과다. 기존 큰 단일 번들 경고와 SSR 하네스의 React key 경고는 남아 있다. 공식 Rating REV13과 개인상 정책 revision 3은 바꾸지 않았다.

실제 production Chromium에서 랭킹 4개 화면 × 320/375/390/1280px의 16개 조합이 통과했다. 선택 유지·초기화·Escape 포커스·팝업/페이지 경계·선수 상세 왕복·실제 새로고침 복원·공식 순위 숫자를 검사했다. 기존 리그/컵/편집/선수 탭 UI 36건과 Swipe Back 71건도 통과했고 런타임 오류는 0건이다. 그래프 검증은 네 폭에서 실제 터치 스크롤/탭, 드래그 억제, 점·숫자·Enter/Space의 정확한 경기 ID, Rating Details를 확인했다. 폭마다 MOM 26개와 일반 평점 10개를 공식 함수와 비교했다. Matches는 선택 시즌 36카드·427요소·36개 disclosure였다. DOM 병목 근거가 없어 가상화를 추가하지 않았다.

원본 6시즌 localStorage 13,345,997 bytes는 QuotaExceededError가 났고 이전 값은 보존됐다. 2시즌 4,477,717 bytes는 정상 저장됐다. 실제 서비스 워커의 bypass를 끄고 JS/CSS를 캐시한 후 offline reload하여 Player Matches·League 상태와 1,152개 경기 ID를 확인했다. 격리 Chromium 프로필은 Windows 파일 핸들이 남을 때 정리를 연기했고, 기능 검증 결과와 구분했다.

독립 최종 코드 리뷰와 수정 후 재검토에서 남은 Critical/Important 결함은 없었다. 작업 중 다음 문제를 발견·수정했다.

- 같은 날짜의 과거 경기들에서 새 연속 기록 루프가 기존 `oldestMatches(newestMatches(source))`와 다른 순서를 만들던 문제를 회귀 테스트로 재현했다. 기존 순서를 재사용하고 추가 평점 계산은 하지 않는다.
- 팀 소속 표시 인덱스에서 미출전 벤치도 포함하던 문제를 공식 `hasPitchAppearance` 조건으로 수정했다. 후반 추가시간 출전도 기존 공식 규칙으로 처리한다.
- 공통 Records 사실 캐시의 키에 평점 revision이 빠져 구버전 평점이 재사용되던 문제를 기존 REV12→REV13 테스트가 검출했다. 기본·전체 capability 재사용 키 모두 revision을 포함한다.
- 첫 전체 테스트의 나머지 실패는 변경 승인된 팀/포지션 순위 의미, 배열 상태 복원, MOM 별과 그래프 markup 및 옛 helper 호출 횟수를 고정한 기대값이었다. 해당 계약만 새 의미에 맞추고 독립 전체 출력 비교·상호작용 검사로 보강했다. 공식 수치 허용 오차 확대나 기존 테스트 삭제는 하지 않았다.

## 복구 작업에서 완료한 내용

네 기능, 필터 상태 이전, 캐시 최적화와 회귀 테스트는 이미 구현되어 있었다. 복구 작업에서는 기능 코드를 중복 작성하지 않고 최종 코드 감사를 다시 수행했다. 새 감사의 Critical/Important/Minor 지적과 판단 유보는 모두 0건이다. 남아 있던 Global CPU, 일반 CPU/SSR, 복원된 Records 조합 경로와 브라우저 최초 진입 측정 및 최종 회귀 검증을 완료했다. 복구 시점 이후 기능 소스 변경은 없다.

기존 `v2.6.8-*.json` 측정 자료와 변경 없는 `v2.6.9-derived.json`, Records 선수 경로의 유효한 11회 측정을 재사용했다. 조합 측정은 unitRecords 복원 이후 다시 수행했다. 최초 샌드박스 브라우저 실행의 자동화 연결 실패는 최소 페이지 재현 검사로 구분했고, 최종 브라우저 검증은 권한을 확장한 동일한 격리 환경에서 모두 통과했다. 사용자 브라우저 프로필이나 실제 사용자 DB에는 연결하지 않았다.
