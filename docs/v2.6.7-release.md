# Football Tracker v2.6.7

기준 커밋: `fc6eab2f6ebd672058692b5f037808d2ffa26a03` (v2.6.6). 중단 전 구현을 보존해 누락된 검증과 회귀 수정을 이어갔다.

## 구현 내용

- Player Detail을 Overview / Matches로 분리했다. Overview의 프로필·핵심 통계·공식 순위·Recent Form·Rank Trend·Active Streaks·공식 개인상·포지션 기록·선발 성과·Role Impact·Goal Types·Chemistry·Career Timeline·Next Milestones·Personal Records를 유지한다. Matches에서는 기존 실제 출전 경기, 최신순 정렬, 평점·득점·도움·출전시간, 지연 계산하는 평점 추적과 경기 상세 이동을 유지한다.
- Matches에서는 Overview의 전체 선수 순위, 파생 통계, Chemistry, 커리어·개인상·Rank Trend 계산을 실행하지 않는다. Overview는 경기 목록을 만들지 않는다. 이적·방출·현재 명단에 없는 ID의 저장 기록과 역사적 소속팀 순위, DNP/빈 범위의 커리어 포지션 대체 규칙을 보존한다. 명단에 없는 선수의 경기 목록은 원래 저장 순서를 유지한다.
- 탭·시즌·대회 필터와 탭별 스크롤을 기존 내비게이션 항목에 저장한다. 화면 교체 직전/직후의 이동, 지연 렌더링으로 아직 도달할 수 없는 스크롤 위치, 사용자의 직접 스크롤을 구분한다. 기존 Back·팀 상세 복귀·히스토리 중복 방지 경로를 사용한다.
- Player / Match / Team 상세에 공통 sticky Back을 적용했다. 기존 스크롤 컨테이너와 콜백을 유지하며, 상단 safe area와 상세 탭의 sticky 오프셋을 처리한다. 다른 화면의 탭 위치는 변경하지 않는다.
- 경기 수정 화면의 대회·스코어 박스에서 경기 정보 편집을 연다. League / Cup / Champions, 시즌, Matchday 또는 유효한 Stage/Series Game, 날짜, 상대 표시 이름, Home/Away 표시를 편집한다. 기존 이벤트 편집을 통해 점수를 바꾸며 별도 임의 점수 입력은 제공하지 않는다.
- 대회 변경은 canonical assignment와 상위 필드를 함께 갱신하고 더 이상 필요하지 않은 Champions pairing/series 정보를 제거한다. 이전/새 대회·시즌의 중복 슬롯, 등록된 양 팀의 슬롯, 진출·탈락·후속 경기, 같은 라운드의 Champions G1/G2 순서, 추첨 참가 자격을 검증한다.
- 저장된 팀 목록 앞에 커스텀 팀이 있어도 컵 참가 자격과 후속 라운드 검증은 기존 공식 16팀 목록을 사용한다. 전체 팀 목록이 필요한 기록 소유권 검사는 그대로 유지한다.
- 경기 ID, 원래 recordedAt, 이벤트 ID·순서·분·교체, 원본 출전·포지션 이력·선발 스냅샷과 SOT를 보존한다. 메타데이터 적용은 최종 저장 전까지 편집기 내부에만 유지한다. 취소는 원본이나 별개의 미완료 드래프트를 지우지 않는다.
- 저장 대기 시점과 저장 완료 후 반영 시점에서 최신 상태를 확인한다. 저장 중 다른 수정·삭제·후속 경기 때문에 변경안이 더 이상 유효하지 않으면 최신 상태를 보존하고, 편집기에 다시 열어야 한다는 상태를 표시한다. 이미 검증된 기본 저장을 실패로 오인해 표시하지 않는다.
- 리그와 컵 모두 기존 헤더 텍스트로 P/W/D/L/GF/GA/GD/Pts를 정렬한다. P/W/D/GF/GD/Pts는 첫 클릭 내림차순, L/GA는 오름차순이며 다시 누르면 반전한다. 다른 지표는 기본 방향으로 시작한다. `#`는 원래 순서를 복원한다. 동률은 공식 순위로 처리하고 표시 순위·공식 계산·원본 배열은 바꾸지 않는다.
- 리그의 기존 크기·열 너비·행 높이·글꼴·색상과 하나의 GF-GA 열을 유지한다. 컵은 리그의 전체 팀 이름·로고·배경·테두리·글꼴·통계 강조를 사용하면서 W-D-L 42px / GF-GA 44px 복합 열과 컵 상태 표시를 유지한다.
- 컵의 Survival Line / Provisional Survival Line, At Risk, Surviving, Eliminated, Not Played, Champion, Runner-up, 각 Stage/Total, Elimination Draw와 Final Replay 경고를 보존한다. 통계 정렬 중에는 행 사이 경계선 대신 원래 공식 순위의 생존 경계를 명시한다. 진출 판정과 상태는 정렬의 영향을 받지 않는다.

## 지원 범위와 데이터 보존

경기 기록의 소유권을 다시 쓰게 되는 기록 팀·fixture ID 변경은 명확한 이유와 함께 차단한다. 특히 원래 `teamId`가 없어 양 팀의 기록으로 취급되는 과거 League/Cup 경기를 단일 소유 팀으로 저장하려는 경우, 경기 정보 적용과 최종 저장을 모두 차단한다. 이 제한은 일반 편집기 저장에도 적용되며 원본 양 팀의 히스토리를 보존한다. 원래 소유 표현을 그대로 유지하는 저장과 소유 팀이 명시된 기록은 계속 지원한다. 상대 표시 이름과 Home/Away 표시는 편집할 수 있다. 기존 후속 토너먼트 기록과 양립할 수 없는 이동도 차단하며, 기록을 삭제하거나 임의로 재배정하지 않는다. 변경하지 않은 오래된 기록의 기존 호환 경로는 유지한다.

Rating REV13, 개인상 정책 revision 3, MOM·Best XI·공식 개인상, 90분 출전시간 제한, 승점·동률·대회 진행 규칙은 변경하지 않았다. localStorage의 검증된 기본 저장, IndexedDB의 보조 저장, 동일 ID Supabase upsert와 기존 저장 키/스키마를 재사용한다. 새 의존성이나 데이터베이스 마이그레이션은 없다. 실제 사용자 데이터나 브라우저 프로필을 테스트에 사용하지 않았다.

Matches의 Rating Details는 더 이상 계산하지 않는 Overview 범위의 HIT/MISS를 만들어 표시하지 않고 `direct match rating`으로 계산 경로를 표시한다. 실제 평점 추적·원시/표시 값·레거시 출처·타임라인 데이터는 유지한다.

## 성능 측정

기존 합성 데이터 367명·1,152경기·2시즌과 더 큰 6시즌 데이터를 사용한다. `fc6eab2`의 독립 소스와 현재 코드를 번갈아 측정하고, 최초 계산·동일 조회·선수 재진입·경기 수정 후 재계산을 구분한다. Node CPU/production SSR 측정과 실제 Chrome 프레임 측정은 서로 다른 지표다. 각 표의 최종 median/p95와 표본은 `docs/performance/v2.6.7-*.json`에 기록한다.

확인한 병목은 리그 Overall/독립 Standings 진입 시 필요하지 않은 전체 Matchday/선수 분석 생성이었다. 기존 `latestLeagueStandings`의 현재/이전 Matchday 경로를 재사용하여 공식 순위와 이동량을 유지한다. History는 기존 전체 스냅샷을 계속 사용한다. 선수 탭은 선택하지 않은 계산 트리와 경기 목록을 분리했다. Records/Awards/News의 기존 캐시·선택 영역 계산·가상화와 초기 정적 import는 유지한다. 측정 근거 없는 추가 캐시나 계산 생략은 도입하지 않았다.

2시즌 CPU/production SSR, 11회 교차 측정, 단위 ms:

| 경로 | 최초 median 이전 → 이후 | 최초 p95 이전 → 이후 | 해석 |
| --- | --- | --- | --- |
| 독립 Standings | 352.85 → 172.26 | 584.84 → 284.80 | 전체 히스토리 생성 제거 |

Matches의 새 컴포넌트 생명주기 재진입은 50.44 → 4.46ms, 경기 수정 후는 554.71 → 4.38ms였다. 6시즌 Matches 최초 median은 2335.47 → 8.47ms였다. 최초 11회 자료의 6시즌 순위 진입 p95에 이상치가 있어 원본을 유지하고 별도 31회 재측정했다. Standings median/p95는 199.44/222.57 → 114.14/142.48ms, Overall은 159.32/187.07 → 116.73/161.20ms였다. History·Cup·Editor Input·Records·Awards·News·Startup Restore도 원본 보고서에 기록했으며 해당 경로에는 별도 속도 향상을 주장하지 않는다.

실제 Chrome의 2시즌 첫 앱 프레임(11회)은 Player Matches median 377.7 → 283.7ms, p95 744.9 → 389.5ms였다. Home median 268.6 → 273.7ms, Overview 363.5 → 365.0ms로 앱 전체 시작이 빨라졌다고 해석하지 않는다. Matches 화면의 지연 콘텐츠 완료·2프레임 대기·강제 GC 후 유지 JS 힙은 별도 11회 비교에서 27.08 → 10.95MiB였다. 이는 이전 통합 화면과 새 Matches 화면의 작업량 차이이며 최대 메모리·브라우저 전체 메모리·장기 누수 검사는 아니다. 첫 프레임 직후 힙 관측은 지연 작업의 일시적 할당을 포함하므로 메모리 개선 근거로 사용하지 않는다.

새 기능 비용도 측정했다. 최종 수정 후 단독 재측정에서 2/6시즌 경기 메타데이터 검증 median은 36.54/46.15ms, 16방향 정렬과 초기화 합계는 0.042/0.040ms였다. 이 수치는 새 기능의 단독 절대 비용이며 기준 버전과 직접 비교하는 속도 개선 수치가 아니다. 비교 가능한 6개 공식 결과 경로의 해시는 전후 일치했다. production entry는 994,301 → 1,014,590 bytes, 동일 zlib gzip 측정은 279,978 → 285,934 bytes로 소폭 증가했다.

## 검증 기록

기준 버전: 전체 1,249/1,249 테스트, 빌드 통과, 기존 lint 경고 43개. 변경 구현의 개별 검증에서는 경기 수정 34개, 선수 탭 14개, 테이블 12개의 새 회귀 테스트를 추가했다. 독립 리뷰에서 재현한 저장 완료 시점의 덮어쓰기와 탭 복원 프레임 경합, 과거 양 팀 기록의 소유 범위 축소, 커스텀 팀이 섞인 컵 참가 자격 불일치를 별도 테스트로 고쳤다.

최종 전체 테스트는 1,309/1,309건 통과했다. TypeScript 검사와 Production Build, Lint, `git diff --check`도 통과했다. Lint 경고 43건은 기준 버전과 동일하며 오류는 0건이다. 최종 독립 감사에서 발견한 커스텀 팀 순서에 따른 컵 참가 자격 불일치를 실패 테스트로 재현해 수정했고, 추가 P1/P2는 발견되지 않았다. 브라우저 UI는 320/375/390px 총 27건, 런타임 오류 0건을 확인했다. 모든 통계의 양방향 정렬·키보드·초기화, 기준 리그 치수, 컵 상태·경계·재경기, 선수 탭·필터·스크롤·상세 복귀, sticky Back을 검사했다. 오프라인 경기의 Champions → 다음 시즌 League 저장에서는 이벤트·출전·recordedAt 보존과 IndexedDB 보조 저장 일치를 확인했다.

## 검증 한계

브라우저 검사는 격리된 Chrome과 합성 데이터를 사용한다. 물리적 휴대전화·실사용 네트워크·실제 사용자 계정/클라우드 데이터베이스 검증을 뜻하지 않는다. Supabase는 직렬화·동일 ID 큐·실패 경로를 로컬에서 검증하며 실제 데이터베이스에 쓰지 않는다. 기존 큰 단일 JS 번들 경고가 남는다. 브라우저 성능의 첫 앱 프레임은 DOM과 다음 animation frame 기준이며, FCP는 로딩 셸일 수 있다. 힙 관측은 해당 시점의 값으로 최대 메모리나 장기 누수 판정은 아니다.
