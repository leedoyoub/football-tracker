# v2.6.5 Best XI / Awards performance

Measured on 2026-11-03 with `node tests/helpers/v265-measure.cjs`. The script extracts baseline `daefede` source into a verified temporary directory and loads the same existing synthetic fixture for both versions. No browser/user storage is read. Three separate process runs; table values are medians in milliseconds. Each season has 367 known players and 576 matches. These are engine timings, not browser frame/interaction measurements.

New scope and candidate caches reuse raw ranking rows, historical positions and exclusive transfer opportunity facts. Match identity, recorded-team membership and credited minutes are indexed before the player traversal; they are not repeatedly searched for absent players. Competition-specific participation terms reuse those facts. Official selection retains deterministic six-family 4-3-3 grouping.

Scope arrays retain at most 48 selections, official presentation results 48, score-policy variants 16, and History result maps 32. Immutable source-array changes and legacy same-array item replacement change revision keys; policy revision is 3 and Rating revision remains 13. The supported Store updates replace changed entities/collections; arbitrary external mutation of fields inside an unchanged object is not a new supported write API.

Monthly award calculations have no current UI/News/event consumer. Compatibility analytics getters evaluate only if a legacy caller explicitly requests them. Matchday reviews, table/player snapshots and movement calculations remain intact. History derives its opened season and selected award scope/menu rather than all six pitches.

Cold Season XI, post-edit recomputation and three-season official records cost more in this fixture because the new policy additionally computes exclusive historical opportunities and competition-specific participation. Cached queries and some narrower queries are cheaper. This release does not claim a universal speedup. No full browser interaction latency, physical mobile-device or user-data-scale benchmark was measured.

## Actual Chromium rendering and inherited limits

`node tests/v265-layout.browser.cjs` reuses the existing repository's headless Chromium/SSR/built-CSS approach with an isolated temporary profile. The [36-case report](v2.6.5-layout.json) covers all six official pitches, Team History, an unchanged Latest XI reference, and the six History tabs at inner widths 288/320/375/390px. Every pitch contains 11 unique selected players and has aspect 3:4. The History tabs have three columns and two rows. All tested 320px-and-wider cases have zero visible overlap, clipping or failed hit-center checks. All official pitches and tabs pass at 288px as well.

At 288px, the saved 4-2-1-3 Team History pitch has three visible name/rating intersections. The unchanged Team Players / Latest XI reference has the exact same three intersections. Both have two overlapping transparent card-padding rectangles at every tested width, with no failed card/visible-element hit centers or border clipping. This is an inherited narrow-layout limit of the specifically requested shared UI; no unrelated pitch/Team Players redesign is included. The probe checks visible elements and actual pointer hit centers, and reports transparent-padding intersections separately rather than treating them as visible collisions.

This probe renders real browser geometry but does not claim full SPA navigation or deployed-user-data testing. Navigation callbacks/state restoration are tested separately by the UI harness. Manual Chrome control ended because Computer Use could not identify the active Windows browser URL confidently enough to enforce policy; the browser access host was also unavailable. No further manual browser action was attempted.
