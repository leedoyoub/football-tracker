# Football Tracker v2.5.5 성능 최적화 보고서

기준: v2.5.4, `2cb89aa3de0afcd59d844e0786d31eb9eba2d183`. 기존 작업물이 없는 clean main에서 시작했다. 기능, 화면, 저장 포맷을 변경하지 않고 계산 재사용과 IndexedDB 연결 수명을 개선했다.

## 측정 조건과 한계

- Windows, Node v24.19.0, Intel Core Ultra 7 256V. 16팀 × 23명, 현재 선수 367명, 2시즌 1,152경기: 시즌별 League 30일/480경기, Cup 48경기, Champions 48경기. Cup/Champions는 일부 진행 데이터이며 완주 시나리오는 기존 테스트로 확인한다.
- 합성 데이터에 이적·방출·현재 명단에 없는 과거 ID, 선발/벤치, 교체, 포지션 변경, 같은 분의 sequence, 추가 시간, 자책골, 현대/레거시 SOT를 포함했다. 실제 사용자 저장소는 사용하지 않았다.
- 각 작업의 새 fixture 첫 계산과 동일 fixture 재조회를 7회 측정했다. TypeScript 로딩과 fixture 생성은 시간에서 제외한다. p95는 7개 표본의 최댓값이므로 정밀한 모집단 p95 추정은 아니다.
- 최초 독립 Before/After 실행에 시점별 변동이 있어, 최종 수치는 같은 프로세스의 독립 모듈 그래프에서 Before/After 순서를 번갈아 비교했다. 원시 표본도 보관한다.
- **모든 시간은 엔진/파생 데이터 계산 시간이다. 화면 진입, React commit, paint, 스크롤 FPS, 이미지 네트워크, 브라우저 저장 I/O 시간은 미측정이다.** 연결된 브라우저가 없고 IAB 생성도 지원되지 않았다. DOM 동일성은 소스 diff로 확인하고 실제 브라우저 동작을 검증했다고 주장하지 않는다.

### 캐시 수명과 메모리

신규 큰 캐시는 Match/players 컬렉션 또는 정규화 timeline을 WeakMap 키로 사용한다. scope 캐시 상한(조합 16, 포지션 64)은 실제 eviction 회귀 테스트로 확인한다. legacy 동일 배열 내 Match 교체 및 events/appearances/duration 교체를 감지한다. 현재 Store의 불변 snapshot 규칙을 따르며, 배열 내부 객체 필드를 직접 수정하는 별도 API는 도입하지 않았다.

Node forced-GC probe: 12회 새로운 snapshot으로 rating/MOM/조합/포지션/appearance index를 조회한 뒤 감시한 matches/players 컬렉션 24개 중 생존 0개. warm-up 후 heapUsed 25.85 → 25.79 MiB. 신규 캐시의 오래된 컬렉션 해제를 확인한 좁은 실험이며 브라우저 heap, peak memory, 모든 기존 캐시의 leak 여부는 미측정이다.

## 재현

`npm ci` 후 `npm test`, `npm run lint`, `npm run build`, `git diff --check`. Windows 실행 정책에서 npm.ps1이 막히면 `npm.cmd`를 사용한다. 전체 객체 기준 비교에는 Git, tar 및 기준 커밋을 포함한 Git history가 필요하다. shallow clone은 history를 가져온 후 실행해야 하며 기준이 없으면 명시적으로 실패한다.

```powershell
git archive 2cb89aa3de0afcd59d844e0786d31eb9eba2d183 src -o .superpowers/v255/baseline.tar
tar -xf .superpowers/v255/baseline.tar -C .superpowers/v255/baseline
$env:V255_BASELINE_ROOT = (Resolve-Path .superpowers/v255/baseline).Path
$env:V255_OUTPUT = '.superpowers/v255/paired.json'
node --expose-gc tests/v255-performance.bench.cjs
node --expose-gc tests/v255-memory.bench.cjs
```

먼저 `.superpowers/v255/baseline` 디렉터리를 생성한다. standalone benchmark는 V255_BASELINE_ROOT 없이 실행한다. V255_SAMPLES(기본 7), V255_ONLY(`|`로 작업 이름 구분), V255_SOURCE_ROOT로 표본/범위/소스를 설정할 수 있다. Node GC probe는 브라우저 leak의 증명이 아니다. 의존성 추가 없음.
