## 2. 측정 방법과 기준 성능

제품 코드 변경 전에 기존 921개 테스트와 build를 실행했고, 원본 엔진 20개 경로 및 화면·작업 15개 경로를 측정했다. 원시 결과는 `v2.5.9-baseline.json`, `v2.5.9-workflows-baseline.json`, `v2.5.9-targets-baseline.json`, `v2.5.9-memory-baseline.json`에 보존했다.

비교 대상은 Git archive로 추출한 독립 v2.5.8 모듈이다. 같은 fixture를 두 구현에 전달하고 실행 순서를 번갈아 7회 측정한다. 각 경로의 최초 계산(cold), 동일 참조 재조회(revisit), 중앙값·p95·7개 원시 표본을 저장한다. p95는 7개 표본의 최대값이므로 장기 지연 분포를 대표하지 않는다. Node v24.19.0 / Intel Core Ultra 7 256V 환경이다. fixture는 16팀, 팀당 23명, 현재 367명, 2시즌, 1,152경기이며 이적·방출·교체·포지션 변경·legacy 기록을 포함한다.

화면 함수는 실제 코드를 결정적 hook 환경에서 호출한다. SSR은 React 서버 렌더링이다. 두 수치 모두 브라우저 paint, 실제 React commit, 입력 지연, FPS와 구분한다. 초기 화면 함수와 모든 하위 분석을 실행한 settled SSR도 별도로 측정한다. 초기 측정에서 Home 약 1.7초, Player Detail 약 1.47초, Highlight Monthly/Review 약 1.4~1.8초의 계산을 확인했다. Milestones 약 1.2초와 비활성 sync 약 11ms는 실제 이전 표본에 존재하며 최신 표본은 별도 기록한다.

## 3. 전체 후보 15개 분석과 적용 판단

최종 화면 벤치마크의 첫 실행은 테스트 harness 모듈 누적으로 Node heap 한도에 도달해 중단됐다. 13개 경로의 중간 결과를 `v2.5.9-workflows-first-attempt.json`에 보존했다. 최종 실행은 경로별 별도 프로세스에서 동일한 7회 paired 비교를 수행하고 전체17개를 합친다. 중단된 실행이나 중간 수치를 최종 성공 결과로 사용하지 않는다. 브라우저 앱의 heap 한도를 측정한 결과와도 구분한다.

추가로 Cloud Sync 비활성 또는 동일 state이면 엔티티 비교를 시작하지 않는다. 활성 시에는 변경 없는 collection/entity 참조를 건너뛰고 기존 JSON 비교·upsert/delete 순서·payload를 유지한다. SDK, 인증, DB 또는 sync 프로토콜을 변경하지 않았다.

Cup selector의 표시 문자열만 S1~S7로 바꿨다. Stage ID, award 크기, 선택/비선택 색, Final/Replay, 고정 Total, 공식 Cup 및 Provisional Survival Line은 유지한다.

## 5. 입력·스크롤·렌더링 및 리뷰 수정

초기 Home/Player Detail에서 무거운 secondary 계산이 실행되지 않음을 call count로 검사했다. settled Home/Player/Team/Highlight HTML은 기준과 동일하며 Home footer의 의도된 버전 문자열만 정규화한다. idle 및 두 frame fallback의 취소도 검사한다.

1,000개 scroll 이벤트를 하나로 합치고, 지속 이동 중 App 갱신을 기다리며 마지막 위치를 이동 전에 반영한다. 늦은 plot-only patch가 최신 Matchday·focus 등 다른 상태를 덮지 않도록 App은 최신 entry에 부분값을 합친다. pagehide/hidden에서 flush된 새 offset은 같은 핸들러 안에서 현재 route와 나머지 최신 screen state를 보존해 기존 `football-tracker-last-route` 키로 동기 저장한다. 자체 체크포인트를 명시적 복원으로 처리하지 않아 더 새로운 DOM 위치를 되돌리지 않는다.

독립 최종 리뷰는 Critical 0, Important 3, Minor 1을 보고했다. 다음은 모두 재현 실패를 확인한 뒤 수정했다.

이전 리뷰에서 수정한 이슈 4건 외에, 이번 최종 독립 리뷰에서 Important 1건이 추가로 발견되어 RED/GREEN으로 수정했다.

1. 비교 팀 변경 직전 pending scroll이 옛 위치로 복원됨: 동일 geometry의 팀 변경과 실제 외부 offset 복원을 구분. `125→333` 위치 및 navigation checkpoint 보존 검사.
2. 같은 Draft의 일시 저장 실패 후 재시도가 생략됨: 실패 상태만 재시도 허용, 성공·대기 중 중복은 생략. 최종 저장 실패로 취소된 450ms checkpoint도 다시 예약하는 검사 추가.
3. Home 원본 팀 목록과 Teams 공식 팀 목록의 Cup selector key 충돌: Teams 조회에 tournament scope key 추가. historical 팀을 앞에 보존한 catalog에서 Home cache 선행 후 Teams의 정확한 기존 Progress HTML 검사.
4. 버전 정규화의 가운데점이 `?`로 저장됨: `\u00b7`로 정확히 비교. 누락된 두 버전 regex assertion도 2.5.9로 갱신.
5. pagehide 직전 스크롤은 React 상태만 갱신하고 영속화는 후속 effect에 의존함: lifecycle handler 내 직접 `saveLastRoute` 기록으로 수정. handler 반환 직후 저장값 검사와 최신 Matchday 등 plot 외 screen state 보존 검사를 추가했다.

실제 브라우저 inventory는 apps/browsers 모두 비어 있었다. 모바일 터치, paint/commit 수, FPS, 장시간 frame drop, 실제 사용자 입력 지연, 실제 브라우저 heap·PWA 오프라인은 수행하지 않았다. 이 항목의 성공이나 개선을 주장하지 않는다.

## 6. 저장 안전성

저장 키 `football-tracker-v1`, 스키마/DB 버전, primary 검증/read-back, IndexedDB mirror, atomic Import 및 이전 Backup, 최종 저장·epoch·finalized ID 보호를 유지한다. Draft 정책은 450ms 그대로다. 중복 처리 생략은 성공/대기 상태를 대상으로 하며 실패 재시도도 포함한다. 저장 실패 시 메모리 내용을 버리지 않고, 최종 저장 후 늦게 도착한 Draft는 부활시키지 않는다.

기존 전체 회귀 검사에는 저장 실패·복원·IndexedDB 연결/transaction 실패·Import rollback·Backup·Cloud Sync·Navigation/Back·PWA 정책 검사가 포함된다. 실제 사용자 localStorage/IndexedDB를 수정하는 검증은 수행하지 않았다.

## 7. 캐시와 메모리

최근 조회는 객체 identity로 cache hit, 한도 초과 조회는 정확히 재계산되는 것을 검사한다. 기존 appearance index에 선수 ID 검증을 보완했으며 directory 조회당 한 번 수행한다. 새 중복 엔진이나 전역 JSON hash는 없다. News의 milestone map은 기존 WeakMap entry 안에서 64개로 제한한다.

forced-GC probe는 활성 snapshot을 보관하고 서로 다른 128개 조회 결과를 WeakRef로 추적했다. 각 3회에서 기준은 모두128개, 변경 후64·64·32·32개였다. fixture는64경기로 제한하여 query retention을 분리한다. heap delta는 공용 engine cache·V8 비용도 포함하므로 단독 query byte 크기나 browser heap/peak, 보편적 누수 부재의 증거가 아니다. 원시 결과와 범위는 `v2.5.9-memory.json`에 기록한다.
