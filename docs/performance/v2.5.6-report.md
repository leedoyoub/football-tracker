# Football Tracker v2.5.6 구현 및 검증 보고서

기준: `7d076a6a6cae8e86b503b5de357c496c3ae96b3c` / v2.5.5. `main`의 깨끗한 작업 트리에서 시작했다. 사용자 최종 요구사항에 따라 구현, 검증, commit, origin/main push, Pages 배포를 수행한다.

## 구현 결과

- League: Players / Table / History / Matches, 최초 Players. Table 내부 Overall(기본) / Form · Last 5. Form의 최근 경기 수만 3 → 5로 변경하고 시즌·대회·canonical chronology·기존 정렬 기준을 유지한다.
- Cup: Players / Table / Matches, 최초 Table. 실제 현재 Stage와 조회 Stage를 분리한다. Stage 선택은 가로 스크롤, Total은 고정 영역. 미래 Stage를 숨기고 아직 경기 없는 현재 Stage는 표시한다.
- Cup Stage: 항상 16팀. 참가 팀은 선택 Stage 통계, 이전 탈락 팀은 탈락 시점의 누적 통계와 공식 순위. 완료된 Stage의 해당 탈락 팀도 Eliminated 표시. 이후 Stage의 기록이나 탈락은 포함하지 않는다. 경기 없는 Stage의 임의 At Risk 표시를 억제한다. Final/Replay는 기존 공식 판정과 일치한다.
- Cup Total: 공식 Cup rank와 전체 cumulativeStandings 결합. 16팀 일반 행, P/W-D-L/GF-GA/GD/Pts, Champion/Runner-up/Stage 성적 또는 Active 상태. Provisional/Final Standings 표시. 미리보기 및 View All 16 / Show Survival Line 제거.
- Champions: Players / Bracket / Matches, 최초 Bracket. 추첨·대진표·시리즈 판정·팀 이동 및 기존 가로 스크롤 JSX를 보존한다.
- Players: 각 대회 Ranking → Award Race → Best XI / Best XI Race 순서. 기존 지표·Top 10·View All scope·월간/Stage/Round 선택·선수 이동·수상 계산 유지. 선택된 Players에서만 선수 콘텐츠를 mount한다.
- Matches: 공통 CompetitionMatches 컴포넌트. 선택 시즌/대회의 전체 유효 기록을 최신순 표시. All Teams와 MD/Stage/Round 필터를 함께 적용한다. canonical 기록 팀과 isRecordedForTeam 기준을 사용해 상대 팀에 잘못 귀속시키지 않는다. 선수 현재 로스터에 의존하지 않는다.
- Results: ResultsScreen과 Matches에서 같은 ResultCard 사용. 상대 이름/오른쪽 상대 로고 제거, 기록 팀 로고·팀명, canonical MD/Stage/Round/Game, 고정 우측 스코어와 W/D/L. 팀 로고/이름과 경기 metadata/score는 sibling 버튼이다. Home 작은 Recent Matches 소스는 변경하지 않는다.
- History: 기존 MD slider, 완료 상태, Position History, 비교 팀, 누적 순위표 유지. 아래 MD Results를 모바일 4열로 추가한다. 기록 시각 우선, 레거시는 배열 위치 fallback; 수정 날짜는 정렬에 사용하지 않는다. 원본 matchId로 이동한다.
- 상태: 대회별 메뉴와 Matches 필터, Table mode, Cup 조회 Stage, MD/비교 팀/그래프 포커스/그래프 가로 스크롤을 NavigationEntry에 저장한다. Back의 원래 화면 세로 스크롤 유지. 시즌 변경은 조회 범위와 필터를 초기화한다. lastRoute의 legacy Form을 Table/Form으로 복원하고 cupViewAll을 무시한다.

## 데이터·계산·성능 보존

Rating REV13, MOM, 공식 League/Cup/Champions 규칙, Ranking/Award/Best XI 수식은 변경하지 않았다. competition.ts의 두 기존 함수에는 export만 추가했다. 저장 키 `football-tracker-v1`, Match schema, repository/IndexedDB, Draft, Import, Cloud Sync 비활성화, PWA service worker는 변경하지 않았다. 기존 v2.5.5 rating/MOM·selector·선수 index·Chemistry·DB 캐시를 보존한다.

League History의 기존 snapshot 계산을 `buildLeagueHistory`로 분리하고 `buildSeasonAnalytics`가 재사용한다. 따라서 Table/History는 player snapshots·월간 수상을 강제 계산하지 않는다. 캐시는 source identity와 Rating revision에 의해 무효화된다. Matches에서는 공식 standings selector 및 선수 ranking/award 계산 호출이 0회임을 컴포넌트 테스트로 검증한다. 경기 결과 index와 Cup 조회 Stage도 동일 snapshot 재조회 시 캐시를 재사용한다.

독립 v2.5.4 baseline 모듈 그래프와 기존 전체 객체 동등성 테스트를 유지한다. 의도된 Form만 archived baseline의 chronology/standings 함수로 별도 Last 5 기대값을 계산하고, 모든 다른 History 필드·30일 순위·월간 수상·Player snapshots·Best XI·League/Cup/Champions·모든 ranking metric의 값과 정렬·평점/MOM·Records·News·Latest Changes·Chemistry를 정확 비교한다. epsilon, skip, 테스트 삭제는 없다.

## 성능 비교

기존 v2.5.5 benchmark를 기준 커밋의 독립 모듈 그래프와 현재 코드에서 같은 프로세스로 7회 교대 측정했다. Fixture는 16팀 × 23명, 현재 선수 367명, 2시즌 1,152경기다. 아래는 엔진/파생 데이터 CPU 시간 median(ms)이며, 브라우저 화면 진입 시간은 아니다. [20개 경로의 7회 원시 표본 및 p95](v2.5.6-benchmark.json).

| 경로 | Cold v2.5.5 → v2.5.6 | Revisit v2.5.5 → v2.5.6 |
|---|---:|---:|
| Rating + MOM | 444.18 → 467.27 | 1.70 → 2.01 |
| Home derivation | 3607.73 → 3722.35 | 0.02 → 0.02 |
| League selector | 210.06 → 197.23 | 0.03 → 0.03 |
| Cup selector | 23.28 → 24.52 | 0.02 → 0.01 |
| Champions selector | 21.89 → 24.29 | 0.02 → 0.02 |
| League History | 795.45 → 748.96 | 0.01 → 0.01 |
| Global Ranking | 407.22 → 395.66 | 0.02 → 0.02 |
| Chemistry | 1431.39 → 1411.77 | 8.23 → 7.65 |

| Draft primary save | 103.17 → 94.90 | 34.20 → 33.46 |

CPU 경로의 캐시 재조회 성능을 유지한다. Cold 수치는 실행 시점·시스템 부하에 따른 변동이 있고, UI 전체의 가속이나 모든 경로의 개선을 주장하지 않는다. Rating+MOM/Cup/Champions/Match Detail의 cold 값은 일부 증가했으나 해당 엔진 구현은 바뀌지 않았다. Draft는 메모리 localStorage CPU 경로이며 실제 저장 I/O 시간은 아니다.

재현: `node --expose-gc tests/v256-performance.bench.cjs`. Git/tar와 기준 history가 필요하다. baseline은 임시 디렉터리에 추출하고 정해진 임시 루트 내부임을 확인한 뒤 정리한다. 추가 패키지는 없다.
