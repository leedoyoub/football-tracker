# v2.6.3 measured derivation performance

Compared with v2.6.2 commit `41c55611c710c4d3cd9e2eae5035232c8b574250` using the existing deterministic history fixture. The 1-season fixture contains 576 matches; the 3-season fixture contains 1,728 matches. Both contain 367 players and 16 teams, including transferred, released and removed players. Every fixture seeds saved kickoff formation `4-2-3-1`.

Run `node --expose-gc tests/v263-performance.bench.cjs`. The runner extracts baseline source into a validated temporary directory, uses isolated processes per workflow, alternates baseline/current order, and collects three paired samples per scale with GC outside measured regions. Medians below are milliseconds, before -> after, on Intel(R) Core(TM) Ultra 7 256V, Node v24.19.0. Full samples and the 1-season results are in [v2.6.3-engine.json](v2.6.3-engine.json).

Filter means League plus CB selection and goals metric where applicable. It is a no-op for official events, Home awards and Latest Changes, which have no such filter. Edit removes the final event from the latest first-team League match; delete then removes that match. Mutations use fresh arrays, following Store behavior.

## Adopted changes

- Official event publication derives competition candidates only when that competition is finalized. Existing live candidates remain available through the lazy `competitionAwards` getter. This removes unpublishable award work from Honors and both Records paths. Three-season cold medians improve 10.5% for Honors, 8.5% for official events and 9.4% for player award Records. Removing a result that revokes League completion also avoids provisional League candidate work.
- Position-filter changes reuse the existing unfiltered ranking facts and rating arrays, then select rows and sort the requested metric. Three-season position/metric switching improves 14.49 -> 0.26 ms (98.2%); one season improves 10.60 -> 0.28 ms (97.4%). An initially restored CB filter still derives only its required facts; it does not force an unfiltered aggregation first.
- Existing caches now check item-reference revisions as well as array identity. Same-array replacement, addition, deletion and roster removal cannot hide behind cached official, ranking, News, Latest Changes or season-snapshot results. Revisions compare references without serializing match payloads; these checks intentionally add small warm-query costs (three-season ranking 0.035 -> 0.235 ms; Honors 0.013 -> 0.032 ms). Store's immutable updates remain the primary path. Mutating properties inside the same item object is outside this item-replacement contract.

## Retained paths and limits

Player award grouping, team award counting, ranking components and virtual lists retain their existing implementations; warm grouping costs are small compared with official publication. Honors overview/played scans measured below 2 ms and were retained. Home season awards show no dependable improvement (275.11 -> 281.49 ms at three seasons), so no additional award cache was introduced. Latest Changes retains its feed algorithm and virtualized screen; its source/snapshot invalidation is corrected. Its observed three-season medians are lower, but timing variation alone is not evidence of a dedicated feed speedup; cold feed construction remains the largest measured cost.

*Best XI now selects dedicated 4-5-1 group quotas instead of the baseline's fixed official-style 4-3-3. Its times compare deliberately changed behavior, with eligibility counts checked across versions. Three-season cold time remains about 16 ms; filter and edit costs add about 1 ms for formation/group computation. The cached new result returns in 0.088 ms. All other workflows require identical full-result SHA256 hashes after cold, warm, filter, edit and delete queries; all checks passed, including event IDs, recipient counts and ranking order.

These are local Node CPU measurements, not browser commit, paint, mobile latency or frame-rate measurements. Three samples are a small sample size and sub-millisecond differences are noisy. No broad new feed cache or speculative UI refactor was adopted.

Validation: 8 new performance/cache regression tests pass; the focused award, ranking, History, monthly and Latest Changes regression set passes 73/73. Final repository-wide release checks are recorded separately.
