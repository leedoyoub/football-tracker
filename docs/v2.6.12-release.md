# Football Tracker v2.6.12

기준은 v2.6.11의 `main` 커밋 `476ee014e6714334989cfddb77530a27abd82570`이다. 시작 시 작업 트리는 깨끗했다.

## 경기 MOM

최고 공식 평점이 정확히 10.0이고 여러 선수가 해당 점수를 받으면 `RatingBreakdown.preClamp`가 가장 큰 선수를 선택한다. 제한 전 값도 같으면 포지션, 득점, 도움, 출전시간과 기존 결정적 해시를 순서대로 적용한다. 10.0 미만의 동률에는 기존 규칙을 적용한다. 기존 경기 평점 결과를 재사용하며, 동률 최종 후보만 득점·도움 이벤트를 조회한다.

| 검증 경기 | 포지션 | 제한 전 평점 | 표시 평점 |
| --- | --- | ---: | ---: |
| 10선방 | GK | 10.20 | 10.0 |
| 7득점 | ST | 12.90 | 10.0 |

이 경기의 MOM은 GK에서 ST로 바뀐다. 기존 경기에서 GK의 선방 기록을 24회로 수정한 별도 표본에서는 GK의 제한 전 평점이 14.40이 되어 MOM이 다시 GK로 바뀌었다. 두 경기 모두 공식 평점 상한은 10.0이다. 0.000001점보다 작은 제한 전 차이, 정확히 같은 값과 해시, 세 명 이상 동률, 늦은 포지션 변경, 교체 출전과 중복 선수 ID가 있는 계산 입력을 검증했다.

## 공식 평점·파생 결과

Rating REV13의 평점식, 경기 및 평균 평점, 평점 순위와 표시 방식은 동일하다. 제한 전 값은 경기 MOM 결정에만 새로 사용한다. 기존 Rating Details 진단 표시는 유지한다. 결승 Player of the Final은 기존 공통 동률 함수를 그대로 사용한다.

- Player Matches·Match Detail·Recent Form의 MOM 강조, 선수별 시즌·대회·통산 MOM, Global Ranking·League Players·Home과 Comparison의 MOM, 선수 Records와 역사적 리더보드는 경기 원본에서 다시 계산한다.
- Award Race, 공식 시즌·리그·전후반기·월간 및 대회 수상은 기존 공식을 사용한다. MOM 횟수가 기존 동점 우선순위에 반영되는 경우 수상자나 선발 순서가 바뀔 수 있다. 테스트 표본의 기존 MVP 평가 점수와 평점 기반 Best XI 결과는 동일했다.
- History, 시즌 분석, Season Recap, News, Latest Changes, What Changed와 선수 마일스톤도 새 MOM에 맞춰 계산한다. 10번째 시즌 MOM 마일스톤이 같은 경기에서 GK에서 ST로 이동하는 것을 확인했다.

## 캐시와 기존 데이터

`MOM_POLICY_REVISION = 1`을 경기 MOM 메모와 MOM이 포함된 랭킹 자료, 선수·Records, 공식 수상·History, 시즌 분석, News·Latest Changes, Match Changes 및 Recap 캐시에 반영한다. 평점 breakdown 캐시, Rating REV13, MOM이 없는 Rank Trend·출전 기반 Starting XI·대회 진행 캐시는 기존 판단 기준을 사용한다. 평점 전용 Records 조회도 MOM 정책 변경만으로 무효화되지 않는다.

과거 경기는 저장된 이벤트와 출전 기록으로 다시 계산한다. 별도 MOM 필드나 마이그레이션이 필요 없다. 같은 ID의 경기 객체 교체, 삭제, 선수 배열 교체, 이적 후 과거 팀 범위, 대회별 합계와 실제 새로고침을 확인했다. 앱의 Store는 선수와 경기 변경을 배열 및 객체 교체로 발행한다.

## 성능 비교

독립 v2.6.11 소스와 v2.6.12에서 동일한 합성 데이터를 사용했다. 2시즌 1,152경기에서 4건과 6시즌 3,456경기에서 12건의 10.0 동률 MOM이 바뀌었고, 나머지 경기의 MOM은 같았다. 모든 경기의 전체 RatingBreakdown과 공식 평점 순위가 일치했다. 평점 순위 비교에서는 동반 표시되는 MOM 횟수만 비교 대상에서 제외했다.

각 셀은 v2.6.11 → v2.6.12의 중앙값 / p95(ms)다. 새로운 소스 배열에서 최초 계산을 번갈아 실행했다. 단일 경기 판정은 기존 평점 계산을 완료한 상태, 랭킹 전환은 평점 인덱스를 만든 상태에서 측정했다. Player Detail은 고정된 자바스크립트 훅 환경에서 Overview 본체를 실행한 시간이다. 브라우저 렌더·저장은 이 CPU 수치와 별도로 검증했다.

랭킹, Player Detail, Records, Recap은 초기 표본의 편차를 확인한 뒤 각각 5회씩 재측정했다. 그 밖의 행은 3회 표본이다. 개별 경기 MOM과 전체 첫 누적 중앙값은 줄었다. 6시즌 Player Overview와 일부 화면의 p95는 증가해 화면 전반의 속도 개선으로 집계하지 않았다. Log Match, Chemistry, 저장과 Records 단일 지표 최적화는 v2.6.11과 같은 구조로 동작한다.

## 검증과 배포

- 전체 테스트 1,403/1,403 통과. 실패·취소·건너뜀 0건. TypeScript, Lint 오류 0건·기존 경고 42건, production build와 `git diff --check` 통과.
- 실제 Chromium의 320·390·1280px에서 기준과 후보 Match Detail, 선수별 MOM 별과 파란 평점, 양쪽 공식 10.0, 골키퍼 선방 배지, Global Ranking의 MOM 지표 전환, Records 1위, 새로고침과 원본 기록 보존을 확인했다. 동일한 세 폭에서 v2.6.11 Log Match 신규·과거 경기 편집, SOT와 선방 수정, 재개, 저장 실패 및 재시도 회귀 검사가 통과했다. PWA 오프라인 복원에서 1,152개 경기 ID와 기존 필터를 확인했다.
- 독립 코드 리뷰는 경기 전용 판정, REV13, 기존 해시 및 배열 교체 기반 무효화를 검토했다. 브라우저 확인은 격리된 Chromium 환경이며, 실제 iPhone/Safari와 실제 사용자 Supabase 쓰기는 검증 범위에 포함되지 않았다.

재실행은 `node --expose-gc tests/v2612-mom.bench.cjs`와 `node tests/v2612-mom.browser.cjs`를 사용한다. 원시 결과 기본 경로는 `.superpowers/sdd/v2612/`다. 배포는 [GitHub Pages 워크플로](https://github.com/leedoyoub/football-tracker/actions/workflows/deploy.yml)에서 실행한다. 공개 footer와 활성 서비스 워커의 버전은 새 익명 세션에서 확인한다.
