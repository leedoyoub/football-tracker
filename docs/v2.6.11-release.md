# Football Tracker v2.6.11

기준은 `main`의 v2.6.10 커밋 `a0c3a6e12db8132cddd4161714e6c6d58368e570`이다. 시작 시 추적 중인 변경과 미추적 파일이 없었고, 로컬과 원격 `main`이 같은 커밋을 가리켰다. v2.6.8의 지연 분석·라우트 저장과 v2.6.9의 Records·랭킹 캐시, v2.6.10의 Player Matches 선방 배지를 기준으로 조사했다.

## Log Match

2시즌 합성 데이터로 Chromium에서 드래프트를 재개한 뒤 이벤트 편집과 SOT를 조작했다. 사용자가 보고한 화면 전체 정지는 재현하지 못했다. 기준 버전에서는 골과 실점 EDIT가 같은 타임라인을 렌더 한 번에 두 번 만들었다. 편집 취소 뒤에도 적용 분이 남아 후속 SOT 입력에서 미리보기 네 번과 Pitch 렌더 두 번이 관측됐다. 같은 이벤트 턴에서 FT 증감 버튼을 연속 실행하면 각각 이전 값으로 계산하는 문제도 재현됐다.

- 이벤트 미리보기는 확정 시간과 현재 이벤트·전술 데이터가 같을 때 선수 자격과 배치가 공유한다. 잘못된 분 입력과 비편집 상태에서는 미리보기를 계산하지 않는다. 편집을 마치거나 취소하면 다음 편집의 시간과 선택 상태가 초기화된다.
- SOT 증감은 React 상태의 최신 값에서 적용한다. Event History 정렬과 Pitch 렌더링의 의존성을 모달 입력에서 분리했다. 복원은 원본 경기 객체가 교체될 때 다시 실행한다. 저장된 경기 수정 시 원본 변경 감지와 복구 실패 처리는 기존 경계를 사용한다.
- 최종 저장은 기존 SOT 검증을 사용한다. 기존 부분 SOT 기록은 그대로 열 수 있으며, 사용자가 SOT를 수정하면 두 값이 필요하다. HT 자동 연결 상태는 드래프트에 저장하고 완료 경기는 기록된 HT·FT를 독립적으로 편집한다.
- 선방 입력은 선발 골키퍼의 공식 합계를 표시한다. 수정을 확정할 때 기존 무시간 합계를 먼저 조정한다. 명시적 감소로 필요한 경우 기록 순서상 뒤쪽의 시간 있는 선방 수를 조정하며 ID·시간·순서를 보존한다. 0으로 줄인 행도 보존한다. 타 골키퍼의 선방은 해당 선수와 횟수를 표시한다. SOT는 선방과 별도로 계산한다.
- 득점자 없는 과거 골의 시간은 선수에게 득점을 부여하지 않고 수정할 수 있다. 이미 저장된 레거시 골 유형과 상대 득점자 정보는 시간 변경 시 보존한다.

## 성능과 공식 기록

- 선수 Records 단일 조회는 평점이 필요한 지표만 평점 상세를 만든다. 공식 출전 구간과 같은 경기·선수 사실을 바탕으로 출전 수를 계산한다.
- 조합 Records와 Chemistry는 경기·팀 내 SOT, 골, 출전 구간과 역할을 조합 사이에 공유한다. Chemistry 정렬은 이미 계산된 조합을 사용한다. 2시즌 화면의 1,040개 카드 목록에 높이를 측정하는 기존 가상 목록을 적용했으며, 펼침 상태는 카드 키에 보관한다.
- What Changed는 기존 전체 연대순 인덱스에서 실제로 넘은 마일스톤을 계산한다. 경기와 선수 소스가 교체되면 인덱스를 갱신한다.
- Comparison은 각 선수 요약을 개별적으로 재사용하고 동일한 시즌·대회 범위의 팀 순위를 공유한다. Global Ranking과 별도인 Comparison 팀 순위의 범위를 유지한다.
- Season Recap은 선정된 시즌의 선수별 경기 인덱스를 선발·교체 계산에 사용한다. 기존 공식 개인상·Best XI·시즌 완료 조건을 사용한다.

전체 저장 검증에서는 이미 확인한 출전 행을 ID로 찾아 같은 관계를 대조한다. 450ms 디바운스, 최신 드래프트 정책, 기본 저장 읽기 검증, IndexedDB 미러, 실패 뒤 재시도, 기존 복구본과 동기화 경계를 유지한다. 원본 전체 데이터 직렬화와 브라우저 쓰기 비용은 저장 시간이 계속 필요한 구간이다.

## 측정 및 검증 상태

CPU 측정은 기준 소스를 `git archive`로 추출하고 2시즌 1,152경기와 6시즌 3,456경기를 동일한 생성기로 만들었다. 브라우저는 로컬에 격리된 Chromium 프로필과 2시즌 저장 데이터를 사용한다. 6시즌의 전체 JSON은 이전 검증에서 Chromium 기본 localStorage 용량을 넘었으므로 CPU 측정에 사용한다. Chromium 기기 에뮬레이션은 실제 iPhone과 Safari의 키보드 동작을 재현하지 않는다.

## 제외한 변경과 한계

v2.6.9에서 성능이 나빠 제외한 `unitRecords` 사전 계산은 도입하지 않았다. 선수 Records 전체 최초 계산은 일관된 개선이 없어 단일 조회와 구분했다. Home·Players에 추가 가상화나 일괄 memo를 적용하지 않았다. 드래프트 타이머를 연장하거나 전체 상태 검증을 캐시로 건너뛰는 방식은 적용하지 않았다.

실제 iPhone·Safari의 화면 정지와 소프트웨어 키보드는 검증 환경에 포함되지 않았다. 화면 폭, 숫자 입력 포커스, 이벤트 순서와 실제 서비스 워커는 격리된 Chromium에서 확인했다. 6시즌 데이터는 CPU 비교에 사용했다. 실제 사용자 데이터나 Supabase 계정 쓰기는 테스트 범위에 포함하지 않았다.

## 회귀 검증

- 전체 자동화 1,391/1,391 통과. 취소와 건너뜀 0건. TypeScript, Lint 오류 0건·경고 42건, production build와 `git diff --check` 통과.
- 320·390·1280px production Chromium에서 신규 경기, 드래프트 재개, 과거 경기 이벤트 세 종류 수정과 취소, 다중 선방과 다른 팀 선방, SOT 검증, localStorage 실패 뒤 재시도와 새로고침을 확인했다.
- 서비스 워커의 실제 오프라인 재시작에서 경기 ID 1,152개와 Player Matches의 League 필터를 확인했다. 2시즌 JSON 4,477,717바이트는 저장됐고, 6시즌 JSON 13,345,997바이트는 `QuotaExceededError`가 발생한 뒤 이전 값을 보존했다. 저장 회귀는 기본 저장 검증, IndexedDB 미러, 기존 복구본, Import/Export와 동기화 경계를 포함한다.
- Swipe Back 71개 사례와 320·375·390·1280px Player Matches·Recent Form을 확인했다. 네 폭에서 MOM 평점과 일반 평점을 공식 값으로 확인했고 터치·마우스·키보드가 지정한 경기로 이동했다.
- 기존 Rating REV13·MOM·Best XI·공식 개인상 테스트와 모든 Records·Chemistry·Recap·Match Changes·News 결과 비교를 통과했다. 의도적으로 바꾼 버전 문자열과 최적화 소스의 바이트 일치 검사는 현재 메타데이터 및 독립 v2.6.10 결과 비교로 갱신했다. 실패를 검출하는 원래 기능 계약은 유지한다.
- 독립 코드 리뷰에서 나온 SOT 자동 연결 상태, 교체 골키퍼의 선방 행, 득점자 없는 과거 골, 분 입력의 미리보기 반복을 수정했다. 수정된 경로를 후속 리뷰와 실행으로 확인했다.

벤치마크 재실행에는 `node --expose-gc tests/v2611-performance.bench.cjs`, `node tests/v2611-editor.browser.cjs`, `node tests/v2611-views.browser.cjs`를 사용한다. 기본 원시 결과 경로는 `.superpowers/sdd/v2611/`이다. 큰 단일 번들 경고와 Windows 임시 브라우저 프로필 정리 지연 경고는 남아 있다.
