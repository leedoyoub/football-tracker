# Football Tracker v2.6.3

## Team History Best XI

- Counts saved kickoff formations within the selected team, season and competition.
  All middle numeric lines merge before frequency counting (for example,
  4-1-2-3 and 4-2-1-3 both contribute to 4-3-3). Equal counts prefer the latest
  canonical match chronology, followed by a stable label ordering.
- Uses valid saved numeric metadata, or a complete validated explicit kickoff
  snapshot. Missing/corrupt history has a visible empty state. It never guesses
  from current tactics, final positions or reconstructed legacy appearances.
- Chooses GK/DEF/MID/FW quotas using each player's summed credited group minutes
  for that historical team. Existing cumulative scores, deterministic ranking,
  REV13 and minimum ceil(40% of recorded team matches) remain unchanged.
- Reuses Pitch, player actions, names, ratings, team crests and goals/assists.
  Five-player lines alternate upper/lower positions; 6–10 use multiple rows.
  Crowded Team History formations get a taller pitch and bounded statistics
  cards. Other Pitch consumers retain their existing presentation.
- Shows selected scope, most-used formation, frequency and eligibility; unfilled
  places remain passive vacant slots. Existing filters and disclosure state persist.

## Measured performance and cache correctness

- Reuses existing unfiltered ranking facts when changing a position filter.
  An initially filtered scope retains its narrower calculation path.
- Official event publication defers candidate derivation for unfinished
  competitions. Explicit Competition Awards access still computes those models.
- Shared reference revision guards invalidate match, player, team and draw
  projections when an item is replaced in the same array. Dependent season,
  News, Latest Changes, Honors and Records projections refresh consistently.
  Source arrays are weakly held and scope maps are bounded.
- Paired engine measurements and full-value equivalence checks against v2.6.2
  are recorded in [the performance report](performance/v2.6.3-engine.json).
  These are synthetic CPU measurements, not browser frame timings. Repeated
  cache hits include the new reference checks; a small warm-query overhead is
  the cost of supporting legacy same-array item replacements.

Three-season median CPU results (3 paired samples; milliseconds):

| Honors first query | 1245.95 | 1114.64 |
| Official events first query | 1152.59 | 1054.45 |
| Records first query | 1273.32 | 1153.99 |
| Team award Records first query | 1169.97 | 1094.40 |

| Latest Changes first query | 2763.03 | 2341.84 |

Home awards and Team Best XI have no claimed speed improvement. Warm cached
queries mostly return below a millisecond; player award Records still regroups
rows (1.90 to 3.12 ms). See raw samples and filter/edit/delete measurements in
the linked report. These medians do not
establish statistically significant improvements on other devices or datasets.

## Compatibility and verification

Official AWARD_433/selectAwardBestXI, award policy revision 2, REV13/MOM,
competition operations, v2.6.2 Progress/full names, IndexedDB schema, raw saved
matches, backup/restore, navigation and service-worker version wiring are preserved.
No data migration is performed. In-place mutation of fields inside an existing
object is not an update contract; Store updates replace source objects/arrays.

Regression coverage includes normalization/counting/chronology, historical scope,
group minutes and aliases/substitutions, eligibility/vacancies, cache replacement,
revoked awards, dynamic layouts, player navigation and unchanged official outputs.
Mobile geometry and server-rendered markup are checked at 264px pitch width.
An interactive browser was unavailable, so actual-device visual/touch behavior
has not been manually verified.

Final local checks: 1,169/1,169 tests pass (28 added), TypeScript passes, lint
passes with 43 existing warnings and no new-file warnings, production build
passes, and `git diff --check` passes. Independent code review found no
remaining correctness blockers. Release metadata agrees at 2.6.3.

The existing large JavaScript chunk warning remains; bundle splitting is outside
this release's targeted changes.
