# Football Tracker v2.5.13

Release date: 2026-10-16 (Asia/Seoul). Baseline: clean `main`, `5fca29a69317922206e64329b3e2928fe662c4e0` (v2.5.12). No existing tracked edits were present. Pre-existing untracked `.superpowers` artifacts were preserved.

## Changes

- Reuse the existing FloatingScrollToTop design on **Player Detail, Records main, Records View All, Results, Players, and Competitions → Matches**. League/Cup/Champions Matches are covered; their other menus do not get a new control. Existing global-ranking/award-race controls retain their observer mode.
- One route-owned button observes native `.app-content` scrolling, appears at 500px, scrolls its own surface smoothly to zero, and hides again at the top. Records categories share this active-page behavior. Route keys and cleanup prevent duplicate/residual controls. The original safe-area/nav offset remains.
- Results, Players and CompetitionMatches use `VirtualCardList`/`MeasuredCardWindow` above 40 rows. Smaller lists retain normal flow. All results remain in the logical dataset; only the current window plus five cards of overscan on each side is mounted. Original card renderers, labels, images, actions and 8px gaps remain.
- Card heights are measured with ResizeObserver and indexed with a Fenwick tree. Scroll updates batch into animation frames. Above-viewport size changes preserve the visible anchor; native smooth scroll-to-top suppresses imperative anchor writes until completion/user interruption so height correction cannot stop the animation midway.
- Player Detail shares one season/competition ranking scope across mounts and players. Three metrics and historical-team rankings reuse canonical data and lookup maps. Career position work is deferred when the selected scope already has minutes. Rank Trend and deferred awards/milestones retain their existing implementations.
- Official season models compute team results without calculating individual awards. Personal award events and competition awards initialize once on demand. Historical position projections are reused within an award period/team. Records computes eight aggregate award metrics plus the selected detail; the selector still exposes the complete catalog.
- Ranking facts establish chronological order once per scope, combine goal/assist accumulation with the existing pass, and cache canonical appearance facts across overlapping award scopes. Already scoped match arrays preserve identity so position-minute caches can be reused.
- NewMatch season badges use a canonical goal/assist-only projection. All kickoff, substitution, position, save, draft, save/edit/restore and rating operations are unchanged.
- Version metadata is consistently 2.5.13 in package.json, package-lock.json and config.ts. No dependencies were added.

## Bottlenecks and implementation files

| Finding | Change |
|---|---|
| Every result/directory card mounted at once | `VirtualCardList.tsx`, `cardWindow.ts`; integrated in ResultsScreen, PlayersScreen and CompetitionMatches |
| Unfiltered Players computed historical roles for the whole directory before displaying cards | `playerDirectoryPosition.ts`: compute canonical roles only for rendered cards; preserve batch position filtering |
| Detail remount allocated equivalent match scopes and rebuilt/sorted the same rankings | `playerDetailRanks.ts`, PlayerDetailScreen; shared identity and O(1) rank lookups |
| Ranking repeatedly sorted the same chronology per player and rebuilt defensive/GK facts for overlapping scopes | `stats.ts`: one chronology sort (368 calls → 1 on the 367-player fixture), weak appearance-fact cache and stable scope inputs |
| Team history triggered personal award calculations; hidden record metrics were built eagerly | `officialAwards.ts`, `awardRecords.ts`, RecordsScreen, RecordsLeaderboardScreen, recordsLeaderboards |
| Goal/assist badges invoked full season statistics including unrelated ratings/MOM/defence | `seasonGoalContributions.ts`, NewMatchScreen |

Command: `node --expose-gc tests/v2513-performance.bench.cjs`.

Five samples per side; p95 is the maximum of five and is therefore noisy. Explicit GC runs between sides. Player Detail receives independent cold data rather than inheriting directory role caches. Full tests/build were not running during the final benchmark.

These measure screen-function CPU and production React SSR, **not browser commit/layout, network download, mobile FPS or user-perceived timings**. “repeat CPU” is a rerender of the same mounted screen. Detail remounts model leaving the screen and opening it again. Awards cold is the first award-record read after the measured screens; Team History cold uses separate fresh source data. ## Deferred work and limits

- Initial bundle splitting is deferred. The existing service worker precaches the shell and caches requested assets; introducing lazy chunks without a verified offline prefetch strategy risks opening an unvisited screen offline. No connected browser is available to measure download/parse/Home paint or safely demonstrate an improvement. Existing bootstrap/PWA logic is retained.
- No broad Store/Context rewrite, extra React.memo layers, Rank Trend rewrite, Team Detail/Chemistry UI or additional scroll buttons. Warm selectors are already inexpensive, and no measured benefit justified these changes.
- Photos/emblems retain their existing components and URLs. Windowing reduces mounted image elements without changing assets or styling.
- Heap retention, actual browser accessibility/visual layout, touch interruption, iPhone safe-area positioning, native smooth animation, real browser Back and installed-PWA/offline refresh were not manually verified. Connected browser inventory was empty. Automated equivalents and unchanged persistence/PWA code provide bounded evidence, not a claim of real-device validation.
- Search/filter latency and cold Detail p95 remain candidates for browser profiling. Performance variance is visible in the raw data; larger sample counts on representative mobile hardware are still useful.
