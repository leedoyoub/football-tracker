# Football Tracker v2.6.8

기준: `82c2c8a9e1975797b55397eac4389d2d1a8a6cc7` (v2.6.7). 기존 작업과 저장 형식, 공식 계산 정책을 보존한다.

## Swipe Back과 일반 Back

Player Detail, Match Detail, Team Detail, Global Ranking, Award Race, Records Leaderboard, Results, Latest Changes, Season Recap, Season Highlight, Chemistry에 적용한다. 기존 App의 Back 콜백을 그대로 호출하며 Team Detail은 기존 전용 Back 경로를 사용한다. 별도 내비게이션 히스토리를 추가하지 않는다.

화면 왼쪽 24px 안에서 시작하는 단일 터치가 오른쪽으로 72px 이상 이동하고, 수평 이동이 수직 이동의 1.6배를 넘을 때 실행한다. 수직 의도, 반대 방향, 20px 초과 되돌림, 다중 터치, touchcancel, 화면 변경·숨김·blur는 후보를 취소한다. 한 제스처는 먼저 소비한 뒤 한 번만 Back을 호출한다. 움직이는 동안 React 상태를 갱신하지 않는다.

입력·편집·Squad Import 화면과 Data Management는 제외한다. Data Management는 비동기 파일 읽기·가져오기·내보내기·인증 작업이 있어 화면 전체를 보수적으로 제외했다. Comparison·Standings·기본 탭처럼 명확한 Back 버튼이 없는 화면은 제외한다. 모달과 실제 팝업 트리거, 입력 필드, 가로 스크롤·SVG·canvas·기존 랭킹 지표 스와이프에서 시작한 터치는 차단한다. 일반 펼침 항목은 팝업으로 취급하지 않는다. 팝업 바깥 터치가 팝업을 닫은 뒤 같은 터치로 Back까지 실행되는 경합도 차단한다.

Player/Match/Team의 공통 DetailBack 디자인과 버튼·콜백을 유지하면서 sticky 위치·배경·blur와 전용 높이 CSS를 제거했다. Back은 콘텐츠와 함께 위로 스크롤되고 상세 탭은 기존 top-0 위치를 사용한다. 기존 탭·필터·스크롤 복원 및 Scroll-to-Top 경로는 유지한다.

## 계산 병목과 수정

- News/공식 개인상: 선수마다 전체 시즌을 반복 탐색하던 등록·출전 자료를 시즌별로 한 번 만들고 역사적 소속 기간에 해당하는 팀 기록을 조회한다. 반기·리그 평가에서 동일 출전시간 자료를 공유한다. 공식 완료 조건을 통과하지 못하는 반기 후보 계산을 생략하며 기존 공식 완료 조건과 기사 결과는 그대로다. 기존 News 소스·revision 소유권 아래 4가지 이벤트 선택 결과를 재사용한다. 완료된 시즌이나 과거 이벤트를 잘라내는 방식은 사용하지 않는다.
- Player Overview: 실제 표시하는 Rating/Goals/Assists의 공식 사실을 전체·역사적 팀 범위에 한 번 누적한다. 불필요한 수비 지표·MOM 전체 행 생성을 제거하고 기존 공식 비교 함수를 사용한다. 중복 선수/경기 ID가 있는 과거 자료는 원래 랭킹 경로로 처리하여 이전 동작을 보존한다.
- Global Ranking: 순위 이동에 필요한 현재/직전 경기일 스냅샷만 만들며 History·News의 전체 스냅샷 경로는 유지한다. 빈 경기일과 이전 경기일 부재 규칙도 동일하다.
- Rank Trend: 지표 사이에서 연대순 출전 사실을 공유하고 포지션별 누적 시간을 증분 갱신한다. 선택 선수와의 직접 비교로 순위를 구하며 매 시점 임시 전체 랭킹 배열을 만들지 않는다.
- Records: 동일 필터의 새 Match 배열이 기존 조합 캐시를 깨뜨리던 경로를 수정하고, 요청한 유닛 자료를 재사용한다. 기존 가상 목록과 모든 그룹·공식 공동 순위를 유지한다.
- Season Recap: Starting XI와 Recap 결과를 기존 소스 배열·항목 revision·선수·팀·완료 상태에 따라 재사용한다. 과거 경기 변경은 새 결과를 만든다.
- 마지막 화면 기록: 직렬화한 값이 실제 저장 값과 같으면 localStorage 쓰기를 반복하지 않는다. 드래프트 자동 저장의 타이밍·검증·IndexedDB 보조 저장·Supabase 큐는 변경하지 않는다.

새 캐시는 범위를 제한하고 기존 immutable 소스 배열과 항목 교체 revision을 사용한다. 저장 스키마나 DB 마이그레이션, 새 의존성은 없다. Rating REV13, 공식 개인상 정책 revision 3, MOM·Best XI·출전시간·동률·대회 진행 정책은 변경하지 않았다.

## 측정과 회귀 검증

모든 CPU 비교는 고정 기준 커밋의 독립 소스와 현재 소스를 번갈아 실행한다. 같은 합성 데이터 367명·2시즌 1,152경기 및 6시즌 3,456경기를 사용하며 워크플로별 독립 프로세스에서 11회씩 측정했다. 모듈 로딩·TypeScript 변환·데이터 생성·명시적 GC는 CPU 타이밍에서 제외한다. 최초 데이터 조회, 같은 조회, 새 컴포넌트 생명주기의 재진입, 경기 수정 후 조회를 구분한다. 화면 CPU는 production SSR의 전체 표시 분석 완료 시간이며 브라우저 paint/idle 대기 시간과 다르다.

News·Latest Changes·Records·Recap·공식 개인상·대회 History·기동 데이터 복원 등 비교 가능한 전체 공용 결과는 이벤트 ID·순서·Map 순서를 포함한 JSON 해시가 일치했다. 별도 회귀 테스트는 모든 News 기사와 4가지 이벤트 옵션, 각 시즌 Latest Changes, 모든 Records 카탈로그·필터, Rank Trend의 모든 경기 시점·지표·대회와 이적·방출·중복 ID·과거 경기 수정/추가/삭제를 독립 기준 소스와 비교한다.

실제 production Chromium에서 320/375/390px 모바일과 1280px 데스크톱 UI 회귀 36건이 통과했다. 공식 테이블 순위·정렬·컵 경계/진행·경기 메타데이터 저장·Player 탭 왕복과 스크롤·팀 Back을 확인했고 런타임 오류는 0건이었다. Swipe Back은 별도로 71건이 통과했다. 여기에는 11개 조회 화면, 잘못된 방향/짧은 동작/마우스/취소, 편집 화면 제외, 모달·팝업·기존 가로 스와이프 차단, 다중 터치, 활성 터치 중 경로 교체·blur·pagehide 취소, 새로고침 후 필터·탭·스크롤 복원이 포함된다. 결과는 `v2.6.8-existing-ui.json`, `v2.6.8-swipe-ui.json`에 있다.

실제 서비스 워커 검증은 bypass를 끄고 온라인에서 JS·CSS 캐시를 만든 뒤 네트워크를 오프라인으로 바꿔 새 문서가 로드될 때까지 기다렸다. Player Matches·League 상태와 저장된 1,152개 경기 ID가 모두 복원됐다. 별도 진단에서 독립 v2.6.7과 수정 전 코드는 캐시 4개·worker 오류 6건, 수정 후는 캐시 6개·worker 오류 0건이고 후속 JS·CSS 요청은 cache-storage 응답이었다. `v2.6.8-offline.json`, `v2.6.8-service-worker.json`에 증거를 보관했다.

최종 전체 자동화 테스트는 1,342/1,342 통과(418.9초), 실패·취소·건너뜀 0건이다. TypeScript 검사와 production build, git diff --check도 통과했다. Lint는 종료 코드 0이며 기존 경고 44건이 남는다. 기존 SSR 테스트 하네스의 React key 경고와 큰 단일 JS 번들 경고도 숨기지 않는다. 독립 전체 코드 감사와 서비스 워커 수정 후 재검토에서 남은 Critical/Important 결함은 없었다.

최종 브라우저 시작 측정은 다른 테스트·벤치마크와 겹치지 않게 2시즌 1,152경기·11회씩 독립 컨텍스트에서 교대 실행했다. 실제 production 빌드를 사용하고 worker는 자산 비교를 위해 bypass했다. 첫 앱 프레임은 화면 h1 다음 프레임이며, 전체 분석 프레임은 선택 화면의 지연 분석 로딩이 사라진 다음 두 프레임이다. FCP는 로딩 셸일 수 있어 이들과 구분한다. `v2.6.8-startup.json`에 모든 표본이 있다.

## 발견한 문제와 처리

- 중복 선수/경기 ID가 있는 자료의 개인 순위가 빠른 경로에서 달라지던 문제를 원래 계산 경로로 우회해 해결했다. 독립 기준 비교를 추가했다.
- Team History의 일반 펼침 항목이 팝업으로 오인되던 문제를 실제 팝업 트리거와 구분했다. 팝업 바깥 터치로 닫는 동작이 Back까지 이어지는 경합은 pointerdown 시점의 차단 상태로 해결했다.
- 복구 후 첫 전체 테스트의 7개 실패는 오래된 버전/변수명 기대값, 새 metric swipe 예외 속성, 가짜 window의 matchMedia 누락, 최적화 이전 소스 전체 고정 비교였다. 버전·역할이 같은 기대값을 갱신하고, 실제 swipe 예외 속성 존재를 먼저 검사한 뒤 그 속성만 정규화했다. 유닛의 모든 계산 코드와 공식 개인상의 전체 공유 점수/자격/가중치/동률 코드는 계속 소스로 고정한다. 달라진 등록 인덱스는 모든 후보 필드와 이적·과거 수정/삭제 결과를 독립 v2.6.7 엔진과 대조하는 검증을 추가했다. 테스트를 삭제하거나 공식 수치 허용 오차를 늘리지 않았다.
- 제한된 실행 환경의 localhost Chromium 디버거 연결 실패는 같은 격리 프로필 테스트를 로컬 브라우저 연결이 가능한 실행 환경에서 재실행해 구분했다. Windows가 합성 임시 프로필의 파일 핸들을 유지한 경우 삭제를 미뤘으며 UI 성공/실패를 덮지 않았다.
- 실제 오프라인 점검에서 서비스 워커가 비동기 cache.open 이후 이미 소비된 Response를 복제해 자산 캐시를 만들지 못하는 오류를 발견했다. 네트워크 응답을 반환하기 전에 복제하고 캐시 쓰기를 fetch 이벤트의 waitUntil에 연결했다. 새 회귀 테스트는 실제 Response 본문을 먼저 소비하고 cache.open을 늦춰 navigation·asset 양쪽의 실패를 재현한다. 캐시 이름·경로·network-first 정책과 데이터 저장소는 유지했다.

## 적용하지 않은 변경과 한계

Store의 Context 전체 재설계, 추가 React.memo, 가상화 재작성, Home 계산의 추가 지연, 화면별 코드 분할은 도입하지 않았다. 기존 Cup Stage·테이블 정렬·Player Matches·Competition Selector의 빠른 경로를 유지한다. 초기 번들 크기만으로 사용 속도 개선을 주장하지 않는다.

iOS 일반 브라우저는 시스템 가장자리 내비게이션을 소유할 수 있으므로 사용자 정의 제스처를 중복 실행하지 않는다. 설치형 standalone PWA와 Android 등 일반 터치 환경에서 사용자 정의 Back을 제공한다. 일반 iOS 브라우저에서는 기존 Back 버튼을 사용한다. 내부 React 히스토리를 브라우저 히스토리에 새로 복제하지 않았으며 시스템 제스처가 앱 밖으로 이동하는 것까지 보장하지 않는다. 시스템 동작을 강제로 가로채는 변경은 하지 않았다.

Chromium의 iOS UA/standalone 어댑터 검사는 플랫폼 분기 검증이다. 물리적 iPhone, 실제 Safari/설치형 PWA, 실제 Android 장치·네트워크의 검증을 뜻하지 않는다. Safari의 시스템 내비게이션과 JavaScript 히스토리의 차이는 [WebKit의 관련 설명](https://bugs.webkit.org/show_bug.cgi?id=248303)도 참고했다. Supabase는 기존 로컬 큐·저장 실패·직렬화 회귀 테스트로 검증하고 실제 사용자 DB에 쓰지 않는다. 기존 큰 단일 번들 경고가 남는다.

실제 Chromium localStorage에 원래 합성 데이터를 그대로 쓰는 용량 검증에서 2시즌 JSON 4,477,717 bytes는 저장됐지만 6시즌 13,345,997 bytes는 QuotaExceededError가 발생했다. 실패 후 이전 값이 보존됨을 확인했다. 이 용량 한계는 두 릴리스에 같은 원본 fixture를 사용하는 브라우저 측정의 제약이다. 저장 스키마·fixture·quota를 바꾸거나 가짜 저장소로 대체하지 않았다. 따라서 6시즌은 CPU·SSR·엔진 측정만 제공하고, 브라우저 시작/입력/저장 측정은 2시즌에서 수행했다.
