# Football Tracker v2.5.14

Baseline: `8bbc388a43cda8b6527fbd4215e2ac18036bcd6c` (v2.5.13). Work began on clean `main`; freshly fetched `origin/main` had zero divergence. Baseline full suite: **1,079 passed, 0 failed**.

## Visible change

Team Detail Overview renders existing Cup/Champions status strings on explicit lines: round/stage first, then `Eliminated` or series progress. `Champion`, `Not Started`, Cup stages and `Final Replay` retain their source meaning. No new status is inferred. The two-column status card remains inside the same four-column grid beside unchanged W-D-L and GF-GA cells. Text wraps at word boundaries without ellipsis. Teams 4×4 and all other card contents, colors and controls are preserved.

## Cache and rendering audit

- Reused existing mutation-time competition revisions/owner, global ranking indexes, first-appearance facts, rating/MOM cache, full League history cache and measured card windows. No new persistent cache, storage key, schema or migration.
- The two latest standings calculations are component-memoized and share a compact weak projection between mounts. An initial remount measurement showed 27.57→39.07ms because those two snapshots were recomputed; the final bounded cache removes that repetition. It keys matches, players and teams by identity, includes rating revision and season, and retains at most 32 season/revision entries per snapshot. Full History always takes priority and its construction/cache remain unchanged. Comparison's team lookup lives only within one memoized summary calculation.
- VirtualCardList retains short-list normal flow and measures long cards using existing per-width bounded caches, anchor correction and scroll checkpoints. Team Matches' long benchmark duplicates recorded fixtures under unique IDs to exercise 72 rows; the standard fixture has 36 per team per season.
- A measured candidate introduced extra wrappers for short Team Matches lists. The final screen renders 40 or fewer results directly through the original ResultCard path; exact baseline HTML is regression-tested. A separate final revalidation/remount artifact measures that affected screen after this correction; earlier candidate short-list samples are identified as superseded.
- Comparison uses the existing ranking window calculation/observer with explicit internal viewport refs, separate for Left/Right. Search inputs stay mounted; selection exclusion and current membership labels are unchanged.
- No additional Scroll-to-Top control, dependencies, Context rewrite or storage/PWA modification.

## Regression evidence and limits

New tests compare all Team Detail displayed player facts, raw competition overviews, latest rank movements, full Match Change maps, completed Recap awards, on-pitch rows, full News/Latest Changes output and official awards against separately archived v2.5.13 modules. Fixtures include transfers, released/missing players, legacy matches, duplicated appearances, zero-minute substitutions, partial/gapped Matchdays, event edits and deletions.

Existing historical tests were adapted only for the authorized presentation/virtual-list integration: logical cards are expanded through the existing test helper, new progress lines are rejoined to their exact source string, and the additive latest-only projection is excluded from historical whole-file identity checks. No statistics, ranking, award or event expected values were changed.

Layout-effect simulation separately verifies independent picker observers, first/middle/final reachability, selection handlers and cleanup. Existing measured-card tests cover anchor updates, resize, shrink, restored positions and scroll-to-top. Source identity checks preserve REV13/rating/timeline, official awards, standings, competition identity/revisions/selectors, unit records, store, types, repository, validation, navigation, scroll checkpoints/card measurement and Teams screen.

Connected UI inventory returned **no apps or browsers**. Actual browser/mobile visual layout, FPS, touch/keyboard focus, native Back/scroll, installed-PWA offline refresh and retained heap were not manually verified. Production React SSR, simulated observers and unchanged persistence/PWA source provide bounded evidence; they are not device measurements.

Performance data records cold versus warm paths, filters, SSR node counts, raw samples, median/p95 and observed heap allocation deltas. Extra synthetic catalog players above 367 have no appearances; the scaling samples do not claim a uniformly active 500-player history.

Measurement-tool correction: the existing Node screen harness created temporary modules with a parent, which retained fixture Stores in `module.children` across repeated runs. A regression test reproduced that retention; the harness now creates parentless temporary modules. The memory-pressured first comparison run was discarded and the corrected run checkpoints raw samples. The initial baseline artifact is retained as invalid diagnostic data, not used for performance claims.

Independent read-only code review and a follow-up review reported no Critical or Important findings. Review covered first-appearance ordering, transfers and historical rank scope, partial/gapped Matchdays, revision invalidation, status meaning, list lifecycle and test adaptations. The review also identified the browser/focus verification limits above; simulated observers supplement but do not replace native-device checks.
